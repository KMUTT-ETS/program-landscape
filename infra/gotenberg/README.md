# Gotenberg image (TH Sarabun New embedded)

Custom image extending `gotenberg/gotenberg:8` with **TH Sarabun New** —
Thailand's Cabinet-mandated standard font for official documents (Cabinet
Resolution, 7 September 2010, requiring 16pt body size for all Thai
government publications).

All PDF output in the Program Landscape app — Council Packs,
briefs, scenario packs, decision records — is generated by Chromium
inside this container. Embedding the font system-wide is how we
guarantee Thai text renders correctly (no tofu boxes) on PDFs that end up
being opened anywhere, on any machine, without Sarabun pre-installed.

## 1. The font files

The four `.ttf` files are **committed to the repository** (since 2026-11-07),
so a fresh clone builds this image with no extra step:

```
infra/gotenberg/fonts/
├── THSarabunNew.ttf
├── THSarabunNew-Bold.ttf
├── THSarabunNew-Italic.ttf
└── THSarabunNew-BoldItalic.ttf
```

The filenames above are what `Dockerfile` expects — do not rename.

### Where they come from

- **SIPA / Software Industry Promotion Agency (Thailand)** — the
  authoritative source. TH Sarabun New was commissioned by SIPA and
  released under a permissive open license that allows redistribution.
- **f0nt.com** — mirror frequently used in Thailand.
- **Google Fonts "Sarabun"** is a *different* typeface (Cadson Demak's
  Sarabun). It is **not** TH Sarabun New and will not satisfy the
  Cabinet requirement for official documents. Do not substitute it.

To replace a file, download it from SIPA, rename it to the dashed form
above (the original zip uses spaces: `THSarabunNew Bold.ttf`), and rebuild.

### Why they are committed

They used to be kept out of git so that every developer sourced them
deliberately. In practice that made `pnpm setup` fail on every clean clone
(the `COPY` lines below abort the build), which is the first thing an
adopting university meets. The license permits redistribution, and the
files are about 1 MB.

Production deployment (prompt 13b) bakes the fonts into the image that
ships in the pack-and-ship tarball — they never need to be fetched from
the Ubuntu prod server.

## 2. Build the image

```bash
docker compose build gotenberg
```

The Dockerfile `COPY` step fails loudly if any of the four `.ttf` files
is missing from `fonts/`. It then runs `fc-cache -f -v` and verifies via
`fc-list | grep -ci sarabun` that at least 4 font faces registered — if
not, the build exits non-zero rather than producing a working-looking
image that silently falls back to a substitute font.

## 3. Verify fonts post-build

```bash
docker run --rm program-landscape-gotenberg:dev fc-list | grep -i sarabun
```

You should see four lines (Regular, Bold, Italic, Bold Italic).

## 4. Run

`docker compose up gotenberg` starts the service on `localhost:3001`
(remapped from the container's default `:3000` to avoid colliding with
Next.js). The health check hits `/health` every 30s.

Gotenberg's HTTP API:
- `POST /forms/chromium/convert/html` — HTML → PDF (what templates use)
- `POST /forms/libreoffice/convert` — Office docs → PDF
- `POST /forms/pdfengines/merge` — merge multiple PDFs into one

The app talks to Gotenberg exclusively via `PdfGenerationService` in
`packages/shared/src/pdf/`. See `docs/pdf-generation.md`.

## Windows/WSL2 note

All files in this directory (Dockerfile, the shell-continuation lines in
it, this README) must be saved with LF line endings. The root
`.gitattributes` enforces this; do not override it. CRLF on the
Dockerfile makes the `fc-cache` step silently skip backslash
continuations and produces a broken image.

## Gotchas observed in other Thai PDF stacks

- **Generic `gotenberg/gotenberg:8` image renders tofu** — it ships with
  Noto Sans and DejaVu only; no Thai font. This is why we build a
  custom image rather than using upstream directly.
- **`word-break: keep-all`** is required in template CSS or Thai wraps
  at character boundaries.
- **`@react-pdf/renderer` cannot embed TH Sarabun New correctly** — it
  does its own font shaping that mishandles Thai tone marks. This is
  why we render React to HTML server-side and let Chromium do the final
  PDF conversion.
