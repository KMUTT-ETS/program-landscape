# Job-108

**Slug:** `job-108` · **Phase:** B · **Kind:** SCRAPE (HTML) · **Cadence:** weekly, Mondays 03:00 · **Status:** ✅ real (since 2026-09-20)

> **Public-sector counterpart to [JobThai](./jobthai.md).** JobThai is a
> private-sector job board; job-108.com publishes Thai government and
> state-enterprise recruitment announcements. Together they are the two
> sources behind the Gap Analyzer's demand side — see
> `docs/methodologies/gap-map.md` §14 for how a request chooses `private`
> (JobThai only), `public` (job-108 only) or `all` (both, the default).

---

## What it is

Thai government and state-enterprise recruitment announcements, published as
individual HTML pages on job-108.com. One announcement usually bundles
several positions (ตำแหน่งที่ 1, 1.1, 1.2 …), each with its own seat count,
salary range, minimum education level and an explicit field-of-study list —
the same shape JobThai's `requiredFieldsRaw` gives on the private side, which
is what makes the two sources comparable at the field-of-study layer.

**Deliberately not captured:**

- **No occupation classification.** JobThai postings resolve to
  `jobthai_occupations` (a two-level category/subcategory taxonomy);
  job-108 postings carry no equivalent. Government rows feed the
  field-of-study layer of the Gap Analyzer only — there is no
  `GapMapOccupation` row, and no `program_jobthai_links`-style link table,
  for job-108 demand. An occupation- or agency-level breakdown of the public
  side is open work (`docs/methodologies/gap-map.md` §15 item 9).
- **No programme links.** Because there is no occupation layer, job-108
  demand never drives `jobthai_demand_alignment` or any other programme-level
  driver — it only ever contributes to a field-of-study row's demand share.
- Salary is captured (`salaryMin` / `salaryMax`) where the announcement states
  one, but is not used by any Gap Analyzer figure today.

### No scraping proxy, and an honest identifying user-agent

`robots.txt` on job-108.com disallows **four AI crawlers by name** and
permits the wildcard (`*`) everywhere **except** `/go.php` and `/url.php`.
The connector therefore identifies itself honestly rather than routing
through a scraping proxy:

```
User-Agent: Program-Landscape/1.0 (+<organisation app URL>; <organisation contact email>)
```

Both values come from the organisation profile (`/admin/organization`) via
`outboundUserAgent()` in `packages/shared/src/institution.ts`; the email is
omitted when unset.

Measured 2026-09-20: the site returns HTTP 200 to any user-agent that is not
literally `curl/*`, so this honest, identifying header is sufficient and
costs nothing over a disguised one. `/go.php` and `/url.php` are never
requested — refused outright rather than relying on the connector never
happening to build such a URL (see the origin guard below).

### The origin guard — three independent layers

A sitemap URL is an operator-editable `SystemSetting` (below), so it is a
value that ultimately comes from a human typing into an admin form, not a
hardcoded constant. That value is checked three times, independently, before
any bytes are requested off it:

1. **Write-time (`assertJob108SettingsValid`, `packages/db/src/job108-settings.ts`).**
   `writeJob108Settings` validates the MERGED result of the current settings
   plus an operator's patch before writing anything, and **throws** on a
   sitemap URL off `https://www.job-108.com` or on `/go.php` / `/url.php` —
   a human is watching at this point, so silently discarding the bad value
   would be worse than a loud rejection. A rejected field never partially
   lands: the whole patch is refused.
2. **Read-time (`parseJob108Settings`, same file).** Reading the stored
   settings back **never throws** — a malformed row must not take the weekly
   connector down — but a stored value that is somehow off-origin or on a
   disallowed path is not handed back either; it silently falls back to the
   default. This is deliberately a different failure mode from layer 1: a
   read-path fallback protects the connector from a database anomaly, not
   from a human decision.
3. **Fetch-time (`fetchJob108Page`, `apps/ingestion/src/job108/fetch.ts`).**
   The function that actually makes the network call refuses any URL whose
   origin is not `https://www.job-108.com`, and any path starting `/go.php`
   or `/url.php`, **before** calling `fetch()` — regardless of how the URL
   reached this function. This is the last line of defence and does not
   depend on either of the settings-layer checks having run; a unit test
   asserts it directly.

## Data shape

Per announcement (`Job108Announcement`, table `job108_announcements`):

| Field | Notes |
|---|---|
| `announcementId` | the site's own id, e.g. `id20256`, parsed from the sitemap `<loc>` |
| `agencyName` | nullable — the model may not find one |
| `publishedDate`, `applicationOpenDate`, `applicationCloseDate` | ISO dates, nullable; Thai Buddhist years (พ.ศ.) are converted (พ.ศ. 2569 → 2026) |
| `status` | `PENDING` / `EXTRACTED` / `FAILED` |
| `contentHash` | SHA-256 of the fetched page — dedup and change detection |
| `sourceLastmod` | the sitemap's own `<lastmod>` — what `planJob108Fetch` compares against to decide whether a page needs refetching |

Per position (`JobPosting`, `source = 'job-108'`, one row per position-type —
**never** one row per seat and never one row per announcement):

| Field | Notes |
|---|---|
| `title` | Thai position name, numbering stripped |
| `positionCount` | seats offered, nullable — never invented when unstated |
| `salaryMin` / `salaryMax` | monthly baht, nullable |
| `minEducationLevel` | the **lowest** level the position accepts — same reading rule JobThai uses. อนุปริญญา (an associate degree) maps to `HIGHER_VOCATIONAL_CERT`; a bare school-level floor (ม.3, ม.6) maps to `VOCATIONAL_CERT`, the lowest listed level |
| `requiredFieldsRaw` | Thai field-of-study strings, verbatim, one array entry per field — see the extraction prompt below for the `และ` handling this schema encodes |
| `qualificationRaw` | verbatim qualification paragraph for that position |
| `descriptionRaw` | duplicates `qualificationRaw` — these pages carry no separate duties section, only a qualification block, so this is honest duplication rather than invention |
| `postedDate`, `postedDateEstimated` | `postedDate` is the announcement's own `publishedDate` when stated, else the fetch date, with `postedDateEstimated = true` in the fallback case — **unlike every JobThai row**, which always carries an estimated batch-receipt date |
| `applicationCloseDate`, `positionCount` | ride along as evidence; `positionCount` is **never** weighted into a demand share (see the methodology doc's unit decision) |

27,617 — exactly private + public.** The public denominator was 45 on the

Verdict distribution at university scope, 76 rows:

| basis | under-served | served | over-served | white-space | supply-unknown | too-few-postings |
|---|---|---|---|---|---|---|
| private | 8 | 11 | 25 | 21 | 2 | 9 |
| public | 6 | 23 | 5 | 21 | 2 | 19 |
| all | 8 | 13 | 31 | 21 | 2 | **1** |

**The blended basis collapses `too-few-postings` from 9 to 1.** That is the
backfill's clearest single effect on what a reader sees: eight fields that
could not earn a verdict from private adverts alone now clear the posting
floor once government demand is counted. Note the public-only column is *not*
a weaker version of the blended one — government demand alone leaves 19 fields
under the floor, because it is concentrated in far fewer disciplines.

**Government field-of-study vocabulary.** 6,101 raw strings, of which **2,247
appear on no JobThai posting at all** and **262 of those clear the 5-mention
taxonomy floor** (`JOB_FIELD_MENTION_FLOOR`) — against **none** before the
backfill, when only 22 government-only strings existed at all. This is the
whole premise of the source: the state advertises for disciplines the private
board does not.

**Report that 262 split, not whole.** **198 are atomic** — strings JobThai's
first-token rule *could* have emitted, so a genuine market absence
(แพทยศาสตร์ 80, ทันตแพทยศาสตร์ 47, วิทยาศาสตร์กายภาพ 176). **64 are compound**
(they contain และ or a space) and JobThai's reader could never have produced
them, so counting those as absences would credit this source with a gap that
is an artefact of the *other* extractor. Medicine and dentistry sitting in
the atomic set is the premise landing as designed.

**None of this reaches the map until the taxonomy is rebuilt.** The strings
are stored; the canonical fields that would carry them are not created until
`pnpm jobthai:fields --apply` runs (≈ $0.10, measured — see below). Until
then `/gap-analysis` still renders 76 rows.

## The extraction prompt

`job108-announcement.v1` (`packages/shared/src/ai/prompts/job108-announcement.ts`)
reads one announcement page and returns its positions as structured JSON. It
is a model prompt rather than a regex, unlike JobThai's field extraction,
because the private-sector parser cannot read this corpus at all: it takes
the first whitespace-delimited token, and government announcements separate
disciplines **with spaces** — on a real page it captured 1 field of 8 (see
`id20256.html` position 1.1, eight fields after "ในสาขาวิชา", space-separated).

**The `และ` rule is the inverse of the private-sector parser's failure
mode**, and it is written directly into the prompt rather than left to the
model to infer: "และ" ("and") routinely sits **inside** a single Thai
discipline name — `การจัดการโลจิสติกส์และโซ่อุปทาน` (Logistics and Supply
Chain Management), `วิทยาศาสตร์และเทคโนโลยีการอาหาร` (Food Science and
Technology) and `อาชีวอนามัยและความปลอดภัย` (Occupational Health and Safety)
are each ONE field. The prompt instructs the model not to treat "และ" as a
separator, with worked examples. See
`docs/methodologies/gap-map.md` §14 for the measured comparison against the
**shipped** JobThai regex, which does split on "และ" — a real, evidenced
defect on the private side that this prompt does not share and does not fix.

Other notable extraction rules:

- **Confidence contradiction guard.** A `positions: []` result (the page was
  not readable as a recruitment announcement — some pages on the sitemap are
  news items, not vacancies) with `confidence > 0.5` is a schema-level
  validation error: an empty result is itself a low-confidence outcome, and
  the schema refuses to let the model report high confidence on "found
  nothing".
- **Any-field sentinel** (`*ANY*`, mirroring JobThai's ทุกสาขา handling) must
  be the position's *only* `requiredFieldsRaw` entry when present — a
  position cannot both name specific fields and accept any field.
- **Education-level floor reading**: same "lowest stated level wins" rule as
  JobThai, extended for a school-level or associate-degree floor that
  JobThai's own enum values don't need to express as often.
- Output is capped at 8,000 tokens (comfortably above the 1–10 positions a
  real announcement bundles) and input truncated at 40,000 characters with a
  visible `[truncated]` marker.

Scrubbing (`scrubPostingText`, shared with JobThai) runs **before**
extraction, not after — gender and age requirements, where present, are
stripped before the text ever reaches the model, so a stripped phrase cannot
end up captured inside a field name.

## Persistence

`packages/db/src/job108.ts`. Key decisions:

- **Position identity derives from content, not order** — a position's
  `externalId` is a hash of its title + qualification text, so a
  re-extraction that reorders two positions does not silently reassign one
  job's identity to another. Positions are deleted and rewritten on each
  successful re-extraction rather than diffed.
- **`heldAnnouncementLastmods()` treats `FAILED` the same as `EXTRACTED`
  for "already handled".** A permanently unparseable page (a withdrawn
  posting, a news item swept into the sitemap) would otherwise be due on
  every run forever, at a model call each time. `pnpm job108:backfill
  --retry-failed` is the deliberate escape hatch that revisits `FAILED` rows.
- **Every row carries `ingestionRunId`.** Omitting it is the class of defect
  that has left rows invisible to `realDataWhere()` three times elsewhere in
  this repository (see the memory note on that).
- `createMany` for positions rather than a create loop, inside a 30-second
  transaction window (raised from Prisma's 5s default) — a lesson carried
  over from the kku-publications backfill, where a per-row loop's held lock
  plus the default timeout failed whole announcements under connection-pool
  contention.

## The weekly connector

`Job108Connector` (`apps/ingestion/src/connectors/sources/job-108/connector.ts`).
Discovery reads the sitemap; failing to read it fails the whole run — without
it there is nothing to do (mirrors `kku-research`'s "both sources failed"
hard-stop). A single announcement's fetch or extraction failure is recorded
against **its own row** via `recordJob108Failure` and the run continues — one
withdrawn posting, news item, or transient model hiccup must not sink 20-odd
otherwise-good announcements in the same weekly run.

## The resumable backfill

`pnpm job108:backfill` (`apps/ingestion/src/scripts/job108-backfill.ts`) walks
the full sitemap archive once, outside the weekly cadence's 60-per-run cap.

```bash
pnpm job108:backfill                        # dry run — reports, spends nothing
pnpm job108:backfill --limit=10 --apply     # fetch + extract 10, oldest cap lifted
pnpm job108:backfill --retry-failed         # dry run — also counts FAILED rows due
pnpm job108:backfill --retry-failed --apply --limit=50
```

### On production

The commands above are the dev form. On the prod host the script runs inside
the ingestion container, from the release directory — `docker compose` finds
no compose file anywhere else, which is the first thing this trips people on:

```bash
cd /opt/program-landscape/current

# Dry run. Genuinely free: it fetches sitemap.xml and plans, making no model
# calls. Also the cheapest way to prove the host can reach job-108.com at all,
# which is not a given on KKU's internal network.
docker compose exec ingestion node /app/dist/scripts/job108-backfill.js

# The real run takes ~3 h, so detach it: `docker compose exec` without -d dies
# with the SSH session. /app/logs is bind-mounted to /opt/program-landscape/logs,
# so the log survives on the host.
docker compose exec -d ingestion sh -c \
  'node /app/dist/scripts/job108-backfill.js --apply > /app/logs/job108-backfill.log 2>&1'

tail -f /opt/program-landscape/logs/job108-backfill.log

# Only after it finishes — this clusters the strings the backfill loaded, so
# running it first does nothing. Unlike the backfill, its dry run is NOT free:
# it makes the same model calls as --apply, to keep the preview truthful.
docker compose exec ingestion node /app/dist/scripts/jobthai-fields.js --apply

# Finally, so the Monday 03:00 cadence registers. IngestionScheduler reads
# cadences from the database only at boot, so without this job-108 stays a
# manual-only source and nobody notices until the data goes stale.
docker compose restart ingestion
```

**A fresh production database has no `job108_announcements` rows**, so the
whole archive is due there even though dev is already backfilled: budget ~3 h
and ~$11 at the dev-measured rate. The script's own estimate falls back to a
documented $0.012/announcement when the database holds no historical
`job108-announcement` calls to derive a rate from, which on a fresh host
reads roughly double the eventual bill.

**`deploy.sh` reconciles `data_sources` from the catalog** (step 6.4) so the
connector's row exists before any of this. Before that step existed, this
script failed on a fresh host with `no DataSource with slug='job-108'` —
migrations create tables, not catalog rows, and the seed that did create them
never runs on production.

**Resumable by construction, not by a checkpoint file.** `planJob108Fetch`
already skips anything stored at the same sitemap `lastmod`, so an
interrupted run is safe and cheap to re-launch — it picks up exactly where
it left off and spends nothing re-doing announcements already written. A run
that dies at announcement 1,400 of 2,000 is not a second bill; the same
command run again continues from 1,401.

**The dry run is free, on purpose** — unlike `pnpm jobthai:fields`, whose dry
run makes the same model calls as `--apply` because its job is to preview
what the model would say. This script's job is to preview a **spend
decision** (due-count × wall-clock × dollars) before it is made, so its dry
run stops before any announcement-page fetch and before any model call.

`--apply` is required to write, fetch a page, or spend a model call. Any flag
other than `--apply` / `--limit=N` / `--retry-failed` is refused outright.

## Calibration — the government extractor vs. the private-sector regex

`pnpm job108:calibrate` (`apps/ingestion/src/scripts/job108-calibrate.ts`).
Read-only (the one write is the standard `AiInference` audit row every model
call makes). Feeds JobThai `qualification_raw` paragraphs to the job-108 AI
extractor — never a real government announcement page — so the two
extraction pipelines can be compared on the identical text. Full write-up and
the measured 120-posting run: `docs/methodologies/gap-map.md` §14. Headline:
the "และ" hypothesis for the regex's under-capture is confirmed but a
**minority** cause (4 of 69 model-only field names, 5.8%); most of the
under-capture is the model simply reading more field names out of a list
than the regex's simpler splitting rule finds.

## Shared field vocabulary

Since `612f744` (2026-09-20), `job_field_taxonomy` is built from raw strings
on **both** demand sources, not JobThai alone (`packages/db/src/job-fields.ts`).
A government-only discipline is exactly as eligible to become a canonical
field as a private-sector one, subject to the same 5-mention floor
(`JOB_FIELD_MENTION_FLOOR`). The admin review page at `/admin/job-fields`
shows, per synonym, which source(s) contributed it
(`synonymSourcesForField`, derived from the postings at read time rather than
stored, so it cannot drift) — load-bearing since `jobthai-bridge.v3`, where a
reviewer approving a field should be able to see when it rests entirely on
government text before that approval starts deciding programme assignments.

## Operator settings

`/admin/external/ai-search` (role-gated on `pdf:admin`, same as
`ExternalAiController`) — `GET` / `PATCH /admin/job108-settings`
(`apps/api/src/admin/external-ai/job108-settings.controller.ts`, backed by
`packages/db/src/job108-settings.ts`). Four keys under a `job108.` namespace,
each one `SystemSetting` row:

| Setting | Default | Notes |
|---|---|---|
| `sitemapUrl` | `https://www.job-108.com/sitemap.xml` | validated per the three-layer origin guard above |
| `requestSpacingMs` | 2,000 | politeness, **not a rate limit job-108.com published for us to honour** — a PATCH below 1,000ms is refused outright, not silently clamped, because hammering someone else's server without an agreement is not an operator convenience |
| `maxAnnouncementsPerRun` | 60 | caps the **weekly cadence's** run; the backfill script's own `--limit` overrides this independently |
| `defaultWindowMonths` | 12 | the Gap Analyzer's default public-demand counting window — always overridden by a `publicWindowMonths` URL parameter when a request supplies one; see `docs/methodologies/gap-map.md` §14 |

A malformed **number** in a stored row falls back to its default silently
(a data-entry typo must not take the weekly connector down); a sitemap URL
off-origin or on a disallowed path, or a spacing below the floor, is
**refused with a specific message** on write — see the origin guard above.
`writeJob108Settings` validates the merged result before writing anything, so
a rejected field never partially lands. Every change is `@AuditLog`-ged.

## PDPA posture

Announcements are published government documents, not personal data.
Residual risks are handled the same way as JobThai: gender and age
requirements are discarded at extraction time, never stored (the same
`scrubPostingText` scrubber both sources share); contact details are
redacted from stored text before extraction, not after, so a redacted phrase
can never end up inside a captured field name.

## Brand mark

`job-108` has no logo asset — scraping or hotlinking one off job-108.com is
not ours to do without an agreement, unlike JobThai's `/brand/jobthai.png`.
Every surface that renders job-108-derived data shows an honest bordered
text chip (`Job-108`) instead, at the same size, spacing and link behaviour
as the image variant — see `apps/web/src/components/data-source-mark.tsx`.

## Deliberate exclusions

Same posture as JobThai:

- Gender and age requirements — discarded at parse time, never stored.
- Contact details (email, phone, LINE ids, handles) — redacted from stored
  text.
- No occupation classification, no programme links (see **What it is**
  above) — the field-of-study layer is the whole of what this source
  contributes.

## Known open items

- ~~**`GAP_MAP_SOURCES`** still lists only `jobthai`~~ — **FIXED 2026-09-22.**
  The cited demand boards are now derived from `demandSourcesFor(basis)`, the
  same function that decides the denominator, so a citation cannot drift from
  the query. `gapMapSourcesFor(basis)` is emitted per request by `mapMeta`
  and overrides the route's static `@Provenance` sources (the interceptor
  merges `{ ...provenance, ...meta }`). **A static list naming both boards
  would have been the mirror of the original bug** — a `basis=private` figure
  citing government announcements its denominator never read — which is why
  this is per-request rather than a one-line constant edit. The Council brief
  keeps the blended list, correctly: it has no basis selector and always
  briefs the default. Adding a third board means adding its slug to
  `DEMAND_SOURCE_NAMES`; omit it and `gapMapSourcesFor` throws rather than
  citing a nameless slug.
- The application-topology admin diagram
  (`apps/web/app/admin/application-topology/topology-data.ts`) does not yet
  carry a job-108 source node or the edges into `dash.gap-analyzer` /
  `ai.gap-brief` that JobThai's tables have — its description text was
  updated to mention job-108 (2026-09-20), but the diagram itself was not
  extended with new nodes/edges.
- **The archive backfill has run on dev (2026-09-21) and NOT in production.**
  A production deployment starts from an empty `job108_announcements` table,
  so `pnpm job108:backfill --apply` is a post-deploy step there, at the same
  ≈ 3 h and ≈ $11 measured on dev.
- **`job108-announcement.v2` is owed.** 5.2 % of announcements needed the
  format-correction retry, clustering on two prompt gaps: ปวท.
  (ประกาศนียบัตรวิชาชีพเทคนิค, a real Thai qualification between ปวช. and ปวส.)
  has no enum mapping, so the model invents `TECHNICAL_CERT` — the same family
  as the `DIPLOMA` defect fixed in `9f2a653` — and the retry then picks a
  valid value **unguided**, which is a quality softness and not only a cost
  one; and `qualificationRaw` cannot be null, which a position stating no
  separate qualification block legitimately is. Not fixed during the backfill
  because editing a versioned prompt mid-corpus would have left it
  half-extracted under two versions.
- **The held-failures rule has now stranded announcements via two different
  bugs** (a duplicate-position collision, and the `DIPLOMA` enum defect).
  `--retry-failed` is the supported operator recovery and it works; what does
  not exist is *automatic* recovery, i.e. the retry-count column with backoff
  that `heldAnnouncementLastmods`'s own comment names as the durable answer.
  Until it exists, every future extraction bug silently strands whatever it
  touched until an operator notices.
