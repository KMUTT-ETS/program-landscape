# Adopter Workshop Documentation (unblocked part) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a Workshop group on the adopter doc site (pages 00–03, the security half of 06, troubleshooting, facilitator), a WSL2 page, tutorial gap fixes, and a committed synthetic sample dataset, so a participant on a clean Windows laptop can reach a working Deep-Dive on sample data.

**Architecture:** Doc pages live under `docs/workshop/` and `docs/guides/`, each with a Thai twin listed in `BILINGUAL_PAGES` and an entry in the hand-written sidebar. The sample dataset is generated by a script under `apps/api/scripts/workshop/` (outside the production build) from the import dataset declarations, so its columns cannot drift from the importer; the XLSX files and a curriculum PDF are committed under `workshop/sample-data/`. Sessions 4–5, the mock API server, the reference solution and the benchmark half of session 6 are out of scope (storyline undecided).

**Tech Stack:** VitePress doc site (`apps/docs-site`), Vitest, `xlsx@0.18.5` (already in `apps/api`), `@kku/db` import declarations, Gotenberg (HTML → PDF, maintainer-side only).

**Spec:** `docs/superpowers/specs/2026-11-07-adopter-workshop-docs-design.md`

## Global Constraints

- Work on branch `feat/generic-adoptor`; it merges to `main` before the workshop (~2026-11-21).
- Every new page under `docs/workshop/` and `docs/guides/windows-wsl2.md` has a `.th.md` twin, is listed in `BILINGUAL_PAGES` (`apps/docs-site/src/manifest.ts`), and appears in `apps/docs-site/.vitepress/sidebar.ts` (English and Thai entries).
- Thai twin: same number of `##`/`###` headings, byte-identical fenced code blocks in the same order, and a cross-link near the top (English page: `> **ภาษาไทย:** มีฉบับภาษาไทยของหน้านี้ที่ [`x.th.md`](./x.th.md)`; mirror the existing twins for the Thai side). Prompts and commands inside code blocks are English in both.
- Session pages link to `docs/tutorials/getting-started.md` and `docs/tutorials/program-deep-dive.md` for shared steps; never copy their steps. Fix gaps in those tutorials instead.
- No retired product names (*Curriculum Compass*, *ทักษทัศน์*, *KKU Curriculum Landscape*).
- No real or personal data anywhere. Never read or copy from `kmutt-data/`. People in sample data are tokens (`Lecturer 001`, `อาจารย์ 001`, employee code `WDU-S001`).
- Sample data is institution-specific only: no AI output, no public-connector data, no pre-computed pipeline results. The sample track runs the real pipeline with the participant's own AI key.
- Invented university: **Workshop Demo University** / **มหาวิทยาลัยสาธิตเวิร์กช็อป**. Not shaped on KMUTT or any real institution.
- AI tool prompts are tool-agnostic plain language; fallback assistant is **opencode** with a free model (name the model, mark it "checked on <date>").
- Docker: Docker Engine inside WSL2 is the main instruction; Docker Desktop is the alternative.
- No Makefile, no `rm -rf` in scripts, `path.join()` for paths, no `any`.
- Pages must only mention `pnpm` scripts that exist and `/admin` routes that exist (enforced by `apps/docs-site/test/tutorial-commands.test.ts` once Task 1 extends it).
- `pnpm docs:build` passes after every task that touches `docs/`, `manifest.ts` or the sidebar.
- Commits: conventional, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Use `git commit -F <file>` (the dev guard refuses some phrases in `-m`).

## Review Focus

1. **A Thai twin whose code blocks drift from the English page** (e.g. a translated comment in a command). Expected: `pnpm docs:build` fails. Pinned by running the build in every page task; Task 1 adds the workshop pages to the twin check via `BILINGUAL_PAGES`.
2. **A page naming a `pnpm` script or `/admin` route that does not exist** (renamed since writing). Expected: the docs-site test fails. Task 1 extends `tutorial-commands.test.ts` to every workshop page and the WSL2 page.
3. **A sample file the importer refuses on the day** (column renamed in a declaration, a reference to a code uploaded later, a year in Buddhist era). Expected: caught in CI, not in the room. Task 2's test validates every committed file, in upload order, against the live declarations.
4. **Committed sample files drifting from the generator** (someone hand-edits an XLSX). Expected: test failure naming the file. Task 2's drift test.
5. **The curriculum PDF the pipeline cannot read** (no รายวิชา section recognised). Expected: the sample track still gets courses, because `programme-courses.xlsx` is part of the sample set; `pnpm curriculum:check` is run on the PDF in Task 3, and the result is recorded.

### Task 2: Synthetic sample dataset

**Files:**
- Create: `apps/api/scripts/workshop/sample-data.ts`, `apps/api/scripts/workshop/write-sample-data.ts`, `apps/api/test/workshop-sample-data.test.ts`, `workshop/sample-data/README.md`, `workshop/sample-data/*.xlsx`
- Modify: root `package.json` (script `"workshop:sample-data": "tsx apps/api/scripts/workshop/write-sample-data.ts"`)

**Interfaces:**
- Consumes: `IMPORT_DATASETS`/the dataset declarations from `@kku/db` (columns, `sheetName`, `references`), `validateSheet(dataset, parsed, ctx)` from `packages/db/src/import/validate.ts`, `parseImportWorkbook(bytes, sheetName)` from `apps/api/src/import/parse.ts`.
- Produces:
  - `SAMPLE_UPLOAD_ORDER: readonly string[]` = `['faculties','departments','programmes','faculty-members','program-faculty','enrollment-metrics','financial-metrics','graduate-outcomes','student-cohorts','alumni-cohorts','admission-campaigns','research-outputs','programme-courses']`
  - `buildSampleRows(slug: string): readonly Record<string, string | number | null>[]` keyed by column **header** (deterministic, no `Math.random`/`Date.now`; seeded PRNG if variety is needed).
  - `sampleFilename(slug: string): string` → `` `${String(index+1).padStart(2,'0')}-${slug}.xlsx` ``.
  - `buildSampleWorkbook(slug: string): Buffer` — one sheet named `dataset.sheetName`, header row = declaration headers, then rows.
  - `WORKSHOP_PROGRAMME_CODE: string` — the programme taken through the pipeline.

Content the builder must use: two faculties (Engineering / วิศวกรรมศาสตร์, Science / วิทยาศาสตร์), three departments, three bachelor programmes (one per department; `WORKSHOP_PROGRAMME_CODE` is the Computer Engineering one), academic years **2021–2025 (Common Era)**, rates as fractions (0.87 not 87), ~12 staff per programme as tokens, ~40 research outputs with invented titles, ~40 courses for the workshop programme with 6-digit numeric codes and every Category filled from the template's values. Group sizes ≥ 5 wherever a column has `groupSizeFor`.

- [ ] **Step 1: Write the failing tests** in `apps/api/test/workshop-sample-data.test.ts`:
  - `every sample file passes the importer` — for each slug in `SAMPLE_UPLOAD_ORDER`, parse `buildSampleWorkbook(slug)` with `parseImportWorkbook`, then `validateSheet` with `references` built from the key values of the slugs before it, `heldRowCount: 0`, `allowShrink: false`, `maxRows: 5000`; assert `result.ok === true` (on failure print the errors).
  - `upload order puts every reference before its user` — for every column with `references`, the referenced dataset's index in `SAMPLE_UPLOAD_ORDER` is lower.
  - `no person is named` — every value in a column whose header contains "Name" on `faculty-members` matches `/^(Lecturer|อาจารย์) \d{3}$/` (adjust to the exact name headers in `staff.ts`).
  - `committed files match the generator` — for each slug, parsing `workshop/sample-data/<sampleFilename(slug)>` yields the same rows as `buildSampleWorkbook(slug)`.
  - `generator is deterministic` — two calls to `buildSampleRows(slug)` are deep-equal.
- [ ] **Step 2: Run** `pnpm --filter api test -- workshop-sample-data`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement** `sample-data.ts` with the interfaces above, reading headers and key columns from the declarations (never hard-coding a header string that a declaration already defines).
- [ ] **Step 4: Implement** `write-sample-data.ts`: writes every workbook to `path.join(repoRoot, 'workshop', 'sample-data', sampleFilename(slug))`, prints one line per file with its row count.
- [ ] **Step 5: Run** `pnpm workshop:sample-data`, then the test. Expected: PASS.
- [ ] **Step 6: Write `workshop/sample-data/README.md`:** what the files are, that every person and number is invented, the upload order, and that `pnpm workshop:sample-data` regenerates them.
- [ ] **Step 7: Confirm** `apps/api/scripts/` is outside the Nest production build (`tsconfig.build.json` / `nest-cli.json`); if it is not, exclude it.
