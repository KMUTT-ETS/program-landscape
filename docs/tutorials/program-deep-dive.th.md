# บทเรียน: ทำให้ Program Deep-Dive ใช้งานได้

> **English:** [`program-deep-dive.md`](./program-deep-dive.md) เป็นฉบับที่ใช้บังคับ หากข้อความขัดแย้งกัน ให้ถือฉบับภาษาอังกฤษเป็นหลัก

**ผลลัพธ์** `/programs/<id>` แสดงเนื้อหาจริง ไม่ใช่หน้าว่าง สำหรับหลักสูตรหนึ่งหลักสูตรของมหาวิทยาลัยท่าน และแท็บ "Setup checklist" ของหลักสูตรนั้นเป็นสีเขียว

**จุดเริ่มต้น** แอปที่ทำงานอยู่ และผู้ดูแลระบบคนแรกลงชื่อเข้าใช้แล้ว หากยังไม่มี ให้ทำ [Getting started](./getting-started.th.md) ก่อน คำสั่งทุกคำสั่งด้านล่างรันจากโฟลเดอร์ราก (root) ของ repository

**เวลาและค่าใช้จ่าย** ประมาณครึ่งวัน เมื่อเตรียมแฟ้มข้อมูลไว้พร้อม ค่า AI ประมาณ USD 0.80 ต่อหลักสูตร ดังนั้นให้รันหนึ่งหลักสูตรก่อน แล้วค่อยรันที่เหลือทีหลัง

## ลำดับการทำงาน

ทำตามขั้นตอนตามลำดับนี้ ขั้นตอนหลังจะอ้างอิงรหัสจากขั้นตอนก่อน และการอัปโหลดที่ระบุรหัสซึ่งระบบยังไม่รู้จักจะถูกปฏิเสธ

## ขั้นตอนที่ 1: ตั้งค่า Organisation profile

1. เปิด `/admin/organization` แท็บ "Identity" เปิดอยู่
2. กรอกข้อมูลในช่อง
   - "Thai name": ต้องตรงกับคอลัมน์ชื่อสถาบันในแผ่นงาน TCAS ทุกตัวอักษร connector ของ TCAS ใช้ชื่อนี้ค้นหาหลักสูตรของท่าน
   - "English name", "Thai short name", "English short name"
   - "Region (Thai)" และ "Region (English)": ใช้อย่างใดอย่างหนึ่งจาก Northeast, Central, North หรือ South เป็นภาษาอังกฤษ ค่านี้ใช้เปรียบเทียบประชากรระดับภูมิภาค มหาวิทยาลัยในกรุงเทพมหานครใช้ Central
   - "OpenAlex institution ID": รหัสของมหาวิทยาลัยท่านบน openalex.org เช่น ค่าที่ขึ้นต้นด้วย `I`
   - "Contact email" ไม่บังคับ ตั้งค่า "Public app URL", "Minimum bachelor intake" และ "Minimum postgraduate intake" หากทราบค่า
3. คลิก "Create organisation" เมื่อกลับมาครั้งต่อไป ปุ่มจะเขียนว่า "Save changes"

ท่านควรเห็นหน้ารีโหลดและมีชื่อของท่านในส่วนหัว

## ขั้นตอนที่ 2: อัปโหลดโครงสร้างองค์กรและหลักสูตร

ชุดข้อมูลแต่ละชุดมีหน้าของตนเองภายใต้ `/admin/data-setup` เปิด `/admin/data-setup` คลิกชุดข้อมูล แล้วในหน้าของชุดนั้น `/admin/data-setup/raw/<slug>` ใช้ปุ่มควบคุมสามอย่างเดิมทุกครั้ง

1. คลิก "Download template" เปิดด้วยโปรแกรมสเปรดชีตแล้วกรอกข้อมูล
2. คลิก "Upload filled template" แล้วเลือกไฟล์ของท่าน
3. ดูประวัติ "Uploads" ไฟล์ของท่านจะอยู่ในรายการนั้น

หากไฟล์ถูกปฏิเสธ จะไม่มีการจัดเก็บอะไรเลย ข้อความจะระบุแถวและคอลัมน์ แก้ไฟล์แล้วอัปโหลดอีกครั้ง "Start over" ในหน้าเดียวกันใช้ล้างชุดข้อมูล

อัปโหลดตามลำดับนี้

1. **Faculties** กรอก "Teaching Mode" ของแต่ละคณะ
2. **Departments**
3. **Programmes**
4. **Staff** (slug `faculty-members`)
5. **Programme Teaching Staff** (slug `program-faculty`)
6. **Enrolment** (`enrollment-metrics`), **Finance** (`financial-metrics`) และ **Graduate Outcomes** (`graduate-outcomes`)
7. **Student Cohorts** (`student-cohorts`), **Alumni Cohorts** (`alumni-cohorts`) และ **Admission Campaigns** (`admission-campaigns`)
8. **Publications** (`research-outputs`)
9. **Programme course lists** (`programme-courses`)
10. **University Rankings** (`ranked-universities`) เทมเพลตมีรายการเริ่มต้นอยู่แล้ว จะอัปโหลดตามนั้นหรือแก้ไขก่อนก็ได้

ท่านควรเห็นการอัปโหลดแต่ละครั้งปรากฏในประวัติ "Uploads" พร้อมจำนวนแถวที่จัดเก็บ

หากมีแฟ้มเหล่านี้ ให้อัปโหลดด้วย

- **Course Evaluations**, **Digital Competency** (cohorts และ modules), **External Grants** และ **External Grant Team**, **Employer Feedback** และ **Staff Salary by Funding**
- **Population Projections**
- **Career Skill Demand** แต่ให้ทำหลังขั้นตอนที่ 5 สร้างทักษะแล้วเท่านั้น และเฉพาะกรณีที่ท่านไม่มี KMITL key (ดู [ทักษะตลาดแรงงาน](#labour-market-skills))

กฎที่กำหนดว่าไฟล์จะถูกรับหรือไม่อยู่ใน [Importing from spreadsheets](../data-import.th.md) สามข้อที่ท่านจะพบ คือ

- คอลัมน์ที่ไม่บังคับละเว้นจากแผ่นงานได้ คอลัมน์ที่จำเป็นละเว้นไม่ได้ และคอลัมน์ที่ชุดข้อมูลไม่รู้จักจะถูกปฏิเสธ
- แถวที่ระบุรหัสหลักสูตร คณะ ภาควิชา หรือพนักงาน ซึ่งไม่อยู่ในการอัปโหลดก่อนหน้า จะทำให้ทั้งไฟล์ถูกปฏิเสธ และระบบจะแสดงรายการแถวเหล่านั้น ให้เพิ่มแถวที่ขาดในแผ่นงานก่อนหน้า หรือลบแถวเหล่านั้น
- การอัปโหลดหนึ่งครั้งรับได้สูงสุด 5000 แถว ไฟล์ที่ใหญ่กว่านี้ให้แบ่งเป็นหลายส่วน

## ขั้นตอนที่ 3: รัน connector สาธารณะ

connector ถูกปิดไว้ในการติดตั้งใหม่ ให้รันแต่ละตัวด้วยมือหนึ่งครั้ง

1. เปิด `/admin/data-sources` แล้วคลิกแหล่งข้อมูล
2. ที่ `/admin/data-sources/<slug>` คลิก "Run now"
3. รอจนการรันแสดงว่า succeeded ในประวัติ

รันตัวเหล่านี้

| แหล่งข้อมูล (slug) | สิ่งที่ต้องมี | สิ่งที่ควรเห็น |
|---|---|---|
| `tcas` | ไม่ต้องมีอะไร อ่านแฟ้ม TCAS สาธารณะ ให้รันหลังขั้นตอนที่ 2 เพราะจับคู่หลักสูตรด้วยชื่อคณะและชื่อหลักสูตรภาษาไทย | จำนวนหลักสูตรที่จับคู่ได้ |
| `un-wpp` | ไม่ต้องมีอะไร ดาวน์โหลดตัวเลขประชากรของสหประชาชาติประมาณ 68 MB | การรันที่ succeeded พร้อมจำนวนแถวที่โหลด |
| `kmitl-skill-mapping` | `KMITL_SKILL_MAPPING_CLIENT_ID` และ `KMITL_SKILL_MAPPING_SECRET_KEY` ใน `.env` | โหลดอุปสงค์ทักษะแล้ว ข้ามได้หากไม่มี key |
| `openalex-works` | `OPENALEX_API_KEY` ใน `.env` (key แบบฟรี) และ OpenAlex institution ID จากขั้นตอนที่ 1 | โหลดผลงานวิจัยแล้ว |
| `job-108` | ไม่ต้องมีอะไร เปิดใช้หากต้องการให้ประกาศรับสมัครงานภาครัฐอยู่ในแผนที่อุปสงค์ | โหลดประกาศรับสมัครงานแล้ว |

หากไม่มี OpenAlex key การรันจะถูกบันทึกเป็น skipped พร้อมข้อความ "OPENALEX_API_KEY is not set. Create a free key at https://openalex.org/settings/api and add it to the environment." ให้เพิ่ม key ใน `.env` เริ่ม `pnpm dev` ใหม่ แล้วรันอีกครั้ง

### ทักษะตลาดแรงงาน {#labour-market-skills}

ระบบเปรียบเทียบหลักสูตรกับทักษะที่นายจ้างต้องการ มีสองวิธีในการโหลดทักษะเหล่านี้

1. รัน `kmitl-skill-mapping` ตามข้างต้น หากท่านมี key แล้วรันคำสั่งนี้หนึ่งครั้ง ก่อนรัน pipeline

```bash
pnpm skills:normalise --source=linkedin --auto-promote
```

   คำสั่งนี้เพิ่มชื่อทักษะของตลาดเข้าใน taxonomy ของท่าน เพื่อให้ทักษะของหลักสูตรจับคู่กับชื่อเหล่านั้นได้ ประมวลผลชื่อเป็นชุดละ 25 ชื่อ ในการติดตั้งหนึ่งแห่ง ประมวลผลประมาณ 5,850 ชื่อ ใช้เวลาประมาณหนึ่งชั่วโมง และมีค่าใช้จ่ายราวหนึ่งดอลลาร์ หากไม่ทำ ระบบจะข้ามการจับคู่อุปสงค์ (demand match) และตัวขับเคลื่อน labour-market alignment กับ demand-match จะว่างอยู่ รายการตรวจสอบ setup จะแจ้งเรื่องนี้
2. หรืออัปโหลด **Career Skill Demand** ที่ `/admin/data-setup/raw/career-skill-demand` หลังขั้นตอนที่ 5 สร้างทักษะแล้ว

## ขั้นตอนที่ 4: แนบไฟล์ PDF หลักสูตร

1. ตรวจสอบไฟล์ก่อน คำสั่งนี้พิมพ์เฉพาะจำนวน

```bash
pnpm curriculum:check "<file.pdf>"
```

ท่านควรเห็นจำนวนรายวิชาและหมวดที่พบ

2. เปิด `/admin/programs/<id>?tab=files`
3. เลือกบทบาท `CURRENT_CURRICULUM` แล้วคลิก "Choose PDF"

ท่านควรเห็นไฟล์อยู่ในรายการพร้อมบทบาทของไฟล์

หาก pipeline อ่านรายวิชาจาก PDF ของท่านไม่ได้ ให้อัปโหลดรายวิชาแทนด้วย **Programme course lists** (ขั้นตอนที่ 2) pipeline จะไม่เขียนทับรายวิชาที่อัปโหลดไว้

## ขั้นตอนที่ 5: รัน pipeline

1. เปิด `/admin/programs/<id>?tab=pipeline`
2. คลิก "Run pipeline"
3. รอ แต่ละ phase จะแสดงสถานะเมื่อเสร็จ

pipeline ใช้ผู้ให้บริการ AI ที่ท่านตั้งไว้ใน `.env` (`AI_PROVIDER` เป็น google, anthropic หรือ openrouter) มีค่าใช้จ่ายประมาณ USD 0.80 ต่อหลักสูตร

ท่านรันจากเทอร์มินัลได้ด้วย

```bash
pnpm programs:pipeline <code>
```

บรรทัดคำสั่งเป็นวิธีที่ปลอดภัยที่สุด หาก worker เริ่มใหม่ขณะที่ pipeline รันอยู่ (เช่น หลังแก้โค้ดในโหมด watch) การรันจะถูกตัดกลางคัน ให้รันอีกครั้ง phase ที่เสร็จแล้วรันซ้ำได้ในราคาถูก

pipeline อนุมัติ digest ของหลักสูตรในนามผู้ดูแลระบบคนแรก จึงไม่ต้องตั้งค่าเพิ่ม ตัวเลข USD 0.80 วัดจากหลักสูตรปริญญาตรีหนึ่งหลักสูตรที่มี 126 รายวิชา โดยใช้ `AI_PROVIDER=openrouter` และไม่มี embedding หลักสูตรที่ยาวกว่านี้มีค่าใช้จ่ายมากขึ้น ตรวจสอบ `/admin/ai-cost` หลังหลักสูตรแรก

**Embedding สำหรับส่วน overlap** ขั้นตอน overlap ใช้ Google (`AI_GOOGLE_EMBEDDING_MODEL`) เสมอ จึงต้องมี Google key แม้ `AI_PROVIDER` จะเป็น anthropic หรือ openrouter key แบบฟรีทำ embedding ได้ประมาณ 1,000 ข้อความรายวิชา แล้วถึงขีดจำกัดรายวัน ขั้นตอนนี้จะรอ ลองใหม่ ยอมแพ้ และทำต่อจากจุดที่หยุดในการรันครั้งถัดไป มหาวิทยาลัยที่มีรายวิชาประมาณ 5,000 รายวิชาต้องใช้ key แบบเสียเงิน หรือต้องรัน pipeline (หรือ `pnpm programs:overlap-prep --apply`) อีกครั้งในวันถัดไป จนกว่าทุกรายวิชาจะถูกทำ embedding ดัชนี overlap จะใช้เฉพาะรหัสรายวิชาที่ซ้ำกัน จากนั้นรัน `pnpm programs:overlap --apply` หรือรัน pipeline เพื่อให้คะแนนใหม่

ในการติดตั้งใหม่ pipeline ยังสร้าง skill taxonomy ของท่านเองโดยอัตโนมัติ หลังอ่านหลักสูตรแล้ว phase 2 จะพบว่าทักษะของหลักสูตรยังไม่ตรงกับอะไรเลย จึงสร้างทักษะจากชื่อในหลักสูตรนั้น แล้วนำผลที่เก็บไว้เดิมไปใช้กับหลักสูตร โดยไม่ต้องให้ AI อ่าน PDF ใหม่ phase ต่อ ๆ ไปใน run เดียวกันจะเห็นทักษะเหล่านั้น หลักสูตรที่มีทักษะอยู่แล้วจะไม่ถูกแตะต้อง ตัวเลือกนี้เปิดไว้เป็นค่าเริ่มต้น ตั้ง `PIPELINE_BUILD_SKILL_TAXONOMY=0` เพื่อปิด

## ขั้นตอนที่ 6: ทำให้ Setup checklist เป็นสีเขียว

1. ในหน้าหลักสูตรเดียวกัน เปิดแท็บ "Setup checklist"
2. อ่านแต่ละรายการ รายการสีแดงจะระบุชุดข้อมูลหรือขั้นตอนที่ขาด
3. แก้ไข แล้วรีโหลดแท็บ

บางรายการไม่เกี่ยวกับบางหลักสูตร หลักสูตรระดับบัณฑิตศึกษาไม่มีรายการ TCAS หรือ digital competency หลักสูตรที่ไม่มีหลักสูตรพี่น้องระดับเดียวกันที่มีรายวิชา จะไม่มีรายการ overlap รายการเหล่านี้ไม่เป็นสีแดง รายการที่ AI เติมซึ่งทำงานในโหมด degraded นับเป็นสีเขียว และแสดงหมายเหตุ "degraded" พร้อมเหตุผล

รายการเกี่ยวกับ admission funnel: หากแผ่นงาน admission-campaigns ไม่มี Planned Seats อัตราการแข่งขันและอัตราการเติมเต็มที่นั่งจะคำนวณจากตัวเลขรอบที่ 3 ของ TCAS ที่เปิดเผยต่อสาธารณะ และ checklist จะแสดงข้อความ "Computed from public TCAS round-3 figures" ส่วน Registration yield ต้องใช้คอลัมน์ Confirmed และ Reported ของแผ่นงานนั้น และไม่มีข้อมูลสาธารณะมาทดแทนได้ ให้กรอก Planned Seats, Confirmed และ Reported หากมี

ตัวขับเคลื่อน JobThai แสดง "not applicable" ในการติดตั้งที่ไม่มี JobThai JobThai เป็นฟีดเชิงพาณิชย์ จึงไม่ใช่ความล้มเหลว

มีเพียงข้อมูลจริงเท่านั้นที่ทำให้รายการเป็นสีเขียว แถวตัวอย่างไม่มีทางทำให้เป็นสีเขียว

ท่านควรเห็นทุกรายการเป็นสีเขียวหรือ not applicable

## ขั้นตอนที่ 7: เปิด Deep-Dive

1. เปิด `/programs/<id>` หากท่านเป็นผู้ดูแลระบบ ส่วนหัวจะมีลิงก์ "Setup checklist" กลับไปที่แท็บ
2. เลื่อนดูแต่ละส่วน

ท่านควรเห็นเนื้อหาจริงในทุกส่วนที่มีข้อมูล ส่วนที่ยังว่างจะบอกว่าต้องการอะไร

## ขั้นตอนที่ 8: ขยายไปทั้งพอร์ตโฟลิโอ

1. ตรวจสอบหลักสูตรที่ทำเสร็จแล้วกับเอกสารต้นทาง
2. รัน pipeline สำหรับหลักสูตรที่เหลือจาก `/admin/programs`: ติ๊กเลือกหลักสูตรแล้วเลือก **Run pipeline · N program(s)** หรือรันทีละหลักสูตรจากแท็บ pipeline ของหลักสูตรนั้น วางแผนค่าใช้จ่ายประมาณ USD 0.80 ต่อหลักสูตร

## หลังอัปโหลดหลักสูตร การรับนักศึกษาและจำนวนนักศึกษา การเงิน หรือผลลัพธ์

มุมมองสรุปรวม (roll-up) จะรีเฟรชเอง ไม่ต้องรันคำสั่ง ในการติดตั้งที่อัปเกรดมาจากก่อนการเปลี่ยนแปลงนี้ ให้รันคำสั่งนี้หนึ่งครั้ง

```bash
pnpm outcomes:refresh-derived
```

## หากทักษะไม่ปรากฏ

ตรวจสอบบรรทัด phase 2 ของหลักสูตรในแท็บ pipeline หากระบุว่าชื่อทักษะยังจับคู่ไม่ได้ หรือเชื่อมต่อผู้ให้บริการ AI ไม่ได้ ให้รันขั้นตอนด้วยมือ

```bash
pnpm skills:normalise --source=program_digest --auto-promote
pnpm programs:approve-pending --rematerialise --program-id=<id>
```

คำสั่งแรกสร้าง taxonomy จากชื่อทักษะในหลักสูตร คำสั่งที่สองนำผลของหลักสูตรที่เก็บไว้มาใช้อีกครั้ง โดยไม่เรียก AI จากนั้นรัน pipeline ของหลักสูตรนั้นอีกครั้ง คำอธิบายฉบับเต็มอยู่ใน [Building your skill taxonomy](../adopters/README.md#building-your-skill-taxonomy)

## เมื่อส่วนหนึ่งว่างแต่มีแถวข้อมูลอยู่

แถวที่มาจากการอัปโหลดจะบันทึกการอัปโหลดที่สร้างแถวนั้นไว้ แอปจะซ่อนแถวที่ตรวจสอบที่มาไม่ได้ หากอัปโหลดสำเร็จแต่ไม่มีอะไรแสดง ให้รัน `pnpm data-sources:sync --apply` แล้วอัปโหลดอีกครั้ง ดู [หากการอัปโหลดไม่ปรากฏ](../data-import.th.md#if-an-upload-does-not-appear)
