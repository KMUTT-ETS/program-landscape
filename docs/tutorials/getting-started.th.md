# Getting started: จากการ clone ใหม่จนแอปทำงานได้

> **English:** [`getting-started.md`](./getting-started.md)

**ผลลัพธ์** ท่านมี Program Landscape ทำงานบนเครื่องแล็ปท็อปของท่าน ท่านได้สร้างบัญชีผู้ดูแลระบบคนแรกแล้ว และลงชื่อเข้าใช้แล้ว

**เวลา** ครั้งแรกใช้ประมาณ 30 ถึง 60 นาที ส่วนใหญ่เป็นเวลาดาวน์โหลด

## 1. ตรวจสอบสิ่งที่ต้องมี

ท่านต้องมีทุกข้อต่อไปนี้ก่อนเริ่ม

1. Git
2. Docker Engine พร้อม Compose v2 ตรวจสอบด้วย `docker compose version`
3. Node.js 24 (24.22.1 ขึ้นไป) รัน `nvm use` ในโฟลเดอร์โครงการเพื่อเลือกเวอร์ชันที่ถูกต้อง
4. pnpm 10 รัน `corepack enable` แล้วโครงการจะใช้เวอร์ชันที่กำหนดไว้
5. AI key ใช้ได้ทั้ง Google Gemini key และ OpenRouter key หากไม่มี key แอปยังเริ่มทำงานได้ แต่ขั้นตอน AI ในช่วงหลังของ workshop จะรันไม่ได้
6. พอร์ตเหล่านี้ต้องว่าง: 3000, 4000, 5432, 6379, 9000, 9001, 3001
7. แฟ้มฟอนต์ TH Sarabun New ทั้งสี่แฟ้ม (ขั้นที่ 4 บอกว่าต้องวางไว้ที่ใด)

**บน Windows** ให้ทำงานภายใน WSL2 ตั้งค่าก่อนตาม
[การติดตั้งบน Windows ด้วย WSL2](../guides/windows-wsl2.th.md) ซึ่งติดตั้ง Git,
Docker และ Node.js ให้ด้วย

**แล็ปท็อปของท่าน** ต้องมีหน่วยความจำอย่างน้อย 16 GB และดิสก์ว่างอย่างน้อย 25 GB
การตั้งค่าจะดาวน์โหลดแพ็กเกจประมาณ 2 GB และสร้าง Docker image ประมาณ 4 GB

**การขอ AI key**

- Google Gemini key ขอได้จาก Google AI Studio (`aistudio.google.com`, "Get
  API key") key แบบฟรีใช้ได้สำหรับหนึ่งหลักสูตร แต่จะหยุดหลังประมวลผลข้อความรายวิชาประมาณ
  1,000 รายการต่อวัน หากต้องการมากกว่านั้นให้เปิดการเรียกเก็บเงินใน Google Cloud
- OpenRouter key ขอได้จาก `openrouter.ai` ("Keys") เติมเครดิตก่อนเริ่ม ประมาณ USD 5
  สำหรับหนึ่ง workshop หากเครดิตหมดระหว่างรัน งานจะล้มเหลวกลางทางพร้อมรหัส "402"

**Embedding** ใช้เฉพาะขั้นตอน overlap ของหลักสูตรและการจับคู่ทักษะกับอาชีพ ส่วนอื่นของ
Deep-Dive ไม่ใช้ เมื่อตั้ง Google key ไว้ ระบบจะส่ง embedding ไปที่ Google เสมอ แม้ผู้ให้บริการหลักจะเป็น
OpenRouter หากมีเพียง OpenRouter key ให้ตั้ง `AI_OPENROUTER_EMBEDDING_MODEL` เป็นโมเดลที่ให้เวกเตอร์
1536 มิติ เช่น `openai/text-embedding-3-small` เลือกโมเดล embedding เพียงโมเดลเดียวแล้วใช้ต่อไป
เพราะเวกเตอร์จากสองโมเดลเปรียบเทียบกันไม่ได้ การเปลี่ยนโมเดลภายหลังต้องทำ embedding ใหม่ทั้งหมด

## 2. ดาวน์โหลดโค้ด

1. Clone repository แล้วเปิดโฟลเดอร์

```bash
git clone <repository-url> program-landscape
cd program-landscape
```

ท่านควรเห็นแฟ้มของโครงการ รวมถึง `package.json` และ `.env.example`

## 3. สร้างแฟ้มสภาพแวดล้อม

1. คัดลอกแฟ้มตัวอย่าง

```bash
cp .env.example .env
```

2. เปิด `.env` ด้วยโปรแกรมแก้ไขข้อความ แล้วตั้งค่า key เหล่านี้ ส่วนที่เหลือให้คงไว้

| Key | ค่าที่ต้องตั้ง |
|---|---|
| `AI_PROVIDER` | `google` หากใช้ Gemini key หรือ `openrouter` หากใช้ OpenRouter key ค่าตัวอย่าง `stub` จะไม่เรียก AI จริง |
| `GOOGLE_AI_API_KEY` | Gemini key ของท่าน หากเลือก `google` |
| `OPENROUTER_API_KEY` | OpenRouter key ของท่าน หากเลือก `openrouter` |
| `NEXTAUTH_SECRET` | สตริงสุ่มที่ยาว |
| `ENABLE_LOCAL_AUTH` | คงเป็น `true` บนแล็ปท็อป เพื่อให้ลงชื่อเข้าใช้ด้วยรหัสผ่านที่ท่านสร้างในภายหลัง |

ตอนนี้ท่านควรมีแฟ้ม `.env` ที่ git ไม่ติดตาม ห้าม commit แฟ้มนี้เด็ดขาด

## 4. รันการตั้งค่าครั้งเดียว

1. วางแฟ้มฟอนต์ TH Sarabun New ทั้งสี่แฟ้มไว้ใน `infra/gotenberg/fonts/` โดยตั้งชื่อว่า
   `THSarabunNew.ttf`, `THSarabunNew-Bold.ttf`, `THSarabunNew-Italic.ttf` และ
   `THSarabunNew-BoldItalic.ttf` แฟ้มเหล่านี้ไม่อยู่ใน repository และ image ของบริการ PDF
   จะสร้างไม่ได้หากไม่มีแฟ้มเหล่านี้ ดาวน์โหลดได้จาก SIPA (สำนักงานส่งเสริมอุตสาหกรรมซอฟต์แวร์แห่งชาติ ผู้เผยแพร่ฟอนต์)
   หรือ f0nt.com แล้วเปลี่ยนชื่อแฟ้มตามข้างต้น รายละเอียดอยู่ใน
   [คู่มือฟอนต์ของ Gotenberg](../_generated/gotenberg-fonts.md) (หรือ `infra/gotenberg/README.md`)
   ฟอนต์ "Sarabun" ของ Google Fonts เป็นคนละแบบและใช้แทนไม่ได้ ตรวจสอบด้วย:

```bash
ls infra/gotenberg/fonts/
```

ท่านควรเห็นแฟ้มทั้งสี่

2. รันสคริปต์ setup

```bash
pnpm setup
```

ท่านควรเห็นการติดตั้งแพ็กเกจ การเริ่ม Docker container การรัน database migration การลงทะเบียนแหล่งข้อมูลทุกแหล่ง (ปิดไว้ทั้งหมด) และการโหลดข้อมูลอ้างอิงทั่วไป และจบโดยไม่มีข้อผิดพลาด

3. ตรวจสอบว่าในฐานข้อมูลของท่านไม่มีข้อมูลของมหาวิทยาลัยอื่นปนอยู่

```bash
pnpm adopter:fresh-check
```

ท่านควรเห็นข้อความ "Fresh-install check passed."

## 5. เริ่มแอป

1. เริ่มเว็บแอป API และ ingestion worker พร้อมกัน

```bash
pnpm dev
```

2. ปล่อยให้ทำงานต่อไป เปิดเทอร์มินัลอีกหน้าต่างสำหรับคำสั่งอื่น

## 6. ตรวจสอบว่าระบบทำงานปกติ

เปิดที่อยู่เหล่านี้ในเบราว์เซอร์

| ที่อยู่ | สิ่งที่ควรเห็น |
|---|---|
| `http://localhost:3000` | แอป ในการติดตั้งใหม่ ระบบจะพาท่านไปหน้า setup |
| `http://localhost:4000/api/v1/healthz` | คำตอบ "ok" สั้น ๆ จาก API |
| `http://localhost:4000/api/v1/ready` | หนึ่งบรรทัดต่อหนึ่งส่วนที่พึ่งพา ได้แก่ ฐานข้อมูล Redis ที่เก็บวัตถุ และบริการ PDF |

หากบรรทัดใดในหน้าสุดท้ายไม่ปกติ ให้รัน `docker compose ps` แล้วรอจน container ทุกตัวแสดงว่า healthy

## 7. สร้างผู้ดูแลระบบคนแรก

**ให้ทำทันที** หน้า setup เปิดให้ทุกคนที่เข้าถึงที่อยู่นี้ได้ และคนแรกที่ใช้จะเป็นผู้ดูแลระบบ หน้านี้จะปิดถาวรเมื่อมีการใช้งานแล้ว

1. เปิด `http://localhost:3000` ท่านจะไปที่ `/setup`
2. กรอก "Your name", "Email", "Password" และ "Confirm password" รหัสผ่านต้องมีอย่างน้อย 12 ตัวอักษร จดไว้ให้ดี เพราะไม่มีระบบรีเซ็ตรหัสผ่าน
3. คลิก "Create administrator"

ท่านควรลงชื่อเข้าใช้แล้วเห็นหน้าแรกของแอป หากไปที่หน้า "Sign in" แทน ให้ลงชื่อเข้าใช้ด้วยอีเมลและรหัสผ่านที่เพิ่งสร้าง เมื่อเปิดการลงชื่อเข้าใช้แบบ local ปุ่มจะเขียนว่า "Sign in with developer credentials"

## 8. สิ่งที่ควรเห็น

ทุกหน้าว่างเปล่า ซึ่งถูกต้องแล้ว การติดตั้งใหม่ยังไม่มีคณะ หลักสูตร นักศึกษา หรือบุคลากร ท่านจะโหลดข้อมูลเหล่านี้ในขั้นต่อไป

## ขั้นต่อไป

ทำต่อด้วย [Get Program Deep-Dive working](./program-deep-dive.th.md) ส่วน workshop ที่สร้างจากขั้นตอนเหล่านี้คือ [Workshop: ติดตั้งและใช้งาน Program Deep-Dive](../workshop/README.th.md)

## หากมีปัญหา

| สิ่งที่ท่านเห็น | สิ่งที่ควรทำ |
|---|---|
| "Environment variable not found: DATABASE_URL" | รัน `pnpm link-env` แล้วรันคำสั่งที่ล้มเหลวอีกครั้ง |
| "Cannot connect to the Docker daemon" | เริ่ม Docker แล้วรัน `pnpm setup` อีกครั้ง |
| "port is already allocated" | หยุดโปรแกรมที่ใช้พอร์ตนั้น แล้วเริ่มใหม่ |
| การลงชื่อเข้าใช้วนซ้ำไม่จบ | รัน `pnpm link-env` แล้วเริ่ม `pnpm dev` ใหม่ |
| api หรือ ingestion หยุดตอนเริ่มพร้อมข้อความว่า key หายไป | ตั้ง `AI_PROVIDER=stub` หรือเพิ่ม key ของผู้ให้บริการที่ใช้ แล้วเริ่ม `pnpm dev` ใหม่ |
| ข้อผิดพลาดเกี่ยวกับ Node หรือการติดตั้ง | รัน `nvm use` แล้วรัน `pnpm setup` อีกครั้ง |
