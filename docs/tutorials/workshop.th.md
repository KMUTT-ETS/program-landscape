# คู่มือ workshop สำหรับผู้จัด

> **English:** [`workshop.md`](./workshop.md)

workshop ครึ่งวันที่ผู้เข้าร่วมแต่ละคนนำแฟ้มข้อมูลของมหาวิทยาลัยตนเองมา และจบด้วย Deep-Dive ของหลักสูตรหนึ่งหลักสูตรที่แสดงเนื้อหาจริง

## สิ่งที่ผู้เข้าร่วมต้องนำมา

1. แล็ปท็อปที่ติดตั้ง Docker, Node.js 20, pnpm 10 และ Git แล้ว
2. AI key: Google Gemini key หรือ OpenRouter key
3. ข้อมูลที่ส่งออกมาเป็นสเปรดชีต ได้แก่ คณะ ภาควิชา หลักสูตร บุคลากร จำนวนนักศึกษา (Enrolment) การเงิน และผลลัพธ์ของบัณฑิต ส่วนรายวิชา การประเมิน และทุนวิจัยเป็นข้อมูลเสริม
4. ไฟล์ PDF หลักสูตรของหลักสูตรหนึ่งหลักสูตร
5. ไม่บังคับ: OpenAlex key แบบฟรี และข้อมูลยืนยันตัวตนของ KMITL

## ส่งล่วงหน้า

ขอให้ผู้เข้าร่วมทุกคนทำรายการนี้ให้เสร็จก่อนวันงาน

1. ติดตั้ง Docker, Node.js 20 และ pnpm 10 แล้วตรวจสอบด้วย `docker compose version`
2. Clone repository แล้วรัน `pnpm setup` หนึ่งครั้ง เพื่อให้การดาวน์โหลดขนาดใหญ่เสร็จก่อน
3. ให้พอร์ต 3000, 4000, 5432, 6379, 9000, 9001 และ 3001 ว่างอยู่
4. ขอ AI key
5. รวบรวมข้อมูลที่ส่งออกมา และลบข้อมูลส่วนบุคคลก่อน: ห้ามมีเลขบัตรประจำตัวประชาชน และห้ามมีวันเกิด
6. ทราบชื่อภาษาไทยของมหาวิทยาลัยตนเองให้ตรงตามที่เขียนในแผ่นงาน TCAS

## เคล็ดลับสำหรับผู้จัด

1. บอกทุกคนให้สร้างผู้ดูแลระบบคนแรกทันที ก่อนแชร์ที่อยู่ให้ใคร
2. ลำดับการอัปโหลดสำคัญ หากไฟล์ถูกปฏิเสธ ให้อ่านข้อความร่วมกัน ข้อความจะระบุแถวที่มีปัญหา
3. pipeline มีค่าใช้จ่ายประมาณ USD 0.80 ต่อหลักสูตร วัดจากหลักสูตรปริญญาตรีหนึ่งหลักสูตรที่มี 126 รายวิชา หลักสูตรที่ยาวกว่านี้มีค่าใช้จ่ายมากขึ้น บอกผู้เข้าร่วมให้รันเพียงหนึ่งหลักสูตร
4. รัน `pnpm skills:normalise --source=linkedin --auto-promote` หนึ่งครั้ง หลังการรัน `kmitl-skill-mapping` และก่อน pipeline ให้เริ่มตั้งแต่เนิ่น ๆ เพราะใช้เวลาประมาณหนึ่งชั่วโมง
5. embedding ต้องใช้ Google key แบบฟรีอาจหยุดทำงานเมื่อถึงประมาณ 1,000 รายวิชา บอกผู้ที่มีรายวิชามากกว่านี้ให้ใช้ key แบบเสียเงิน หรือรันซ้ำในวันถัดไป

## ปัญหาที่พบบ่อยและวิธีแก้

| สิ่งที่ผู้เข้าร่วมเห็น | สาเหตุ | วิธีแก้ |
|---|---|---|
| "... is not a known programmes code. Upload that dataset first, or correct the value." | ไฟล์ระบุหลักสูตร คณะ ภาควิชา หรือพนักงานที่การอัปโหลดก่อนหน้านี้ไม่มี ข้อมูลส่งออกเก่ามักระบุหลักสูตรที่ปิดไปแล้ว | เพิ่มแถวที่ขาดในแผ่นงานก่อนหน้า หรือลบแถวเหล่านั้น |
| "This file has 8002 rows; the limit is 5000. Split it into smaller files." | การอัปโหลดหนึ่งครั้งรับได้สูงสุด 5000 แถว | แบ่งไฟล์เป็นหลายส่วนแล้วอัปโหลดทีละส่วน กรณี Publications พบบ่อยที่สุด |
| "This file has N rows but M are already stored..." | เกิดเฉพาะ class offerings และ programme course lists เมื่อไฟล์เล็กกว่าที่เก็บอยู่มาก ชุดข้อมูลอื่นไม่เป็นเช่นนี้ การอัปโหลดที่แบ่งส่วนจึงผ่านได้ทันที | หากไฟล์เล็กนั้นถูกต้อง ให้ยืนยันการอัปโหลดในแผง |
| ขาดคอลัมน์ที่จำเป็น | ห้ามละเว้นคอลัมน์ที่จำเป็น | เพิ่มคอลัมน์นั้น ส่วนคอลัมน์ที่ไม่บังคับละเว้นได้ |
| คอลัมน์ที่ไม่รู้จักถูกปฏิเสธ | อนุญาตเฉพาะคอลัมน์ที่มีในเทมเพลต | ลบคอลัมน์นั้น |
| "OPENALEX_API_KEY is not set..." และการรันถูกข้าม | ยังไม่มี OpenAlex key แบบฟรีใน `.env` | เพิ่ม key เริ่ม `pnpm dev` ใหม่ แล้วรัน `openalex-works` อีกครั้ง |
| การรัน TCAS จับคู่หลักสูตรไม่ได้เลย | "Thai name" ที่ `/admin/organization` ไม่ตรงกับการสะกดของ TCAS หรือยังไม่ได้อัปโหลดหลักสูตร | แก้ชื่อ อัปโหลดหลักสูตร แล้วรัน `tcas` อีกครั้ง |
| การลงชื่อเข้าใช้วนซ้ำไม่จบ | ไม่มีลิงก์สภาพแวดล้อมของแต่ละแอป | รัน `pnpm link-env` แล้วเริ่ม `pnpm dev` ใหม่ |
| อัปโหลดสำเร็จแต่ไม่มีอะไรแสดง | ขาดแถวของแหล่งข้อมูล (data source) | รัน `pnpm data-sources:sync --apply` แล้วอัปโหลดอีกครั้ง |
| pipeline ล้มเหลวที่ขั้นตอน AI ขั้นแรก | ไม่มี AI key หรือ `AI_PROVIDER` เป็น `stub` | ตั้ง key และ `AI_PROVIDER` ใน `.env` แล้วเริ่ม `pnpm dev` ใหม่ |
