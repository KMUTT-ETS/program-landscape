# คู่มือสำหรับสถาบันผู้นำไปใช้ — Program Landscape

> **ฉบับภาษาไทย** เอกสารนี้เป็นคำแปลของ [`README.md`](../../adopters/README.md) ฉบับภาษาอังกฤษ จัดทำขึ้นเพื่อให้นักพัฒนาและทีมไอทีของมหาวิทยาลัยไทยใช้เป็นเอกสารหลักได้โดยตรง ในกรณีที่ข้อความในฉบับภาษาไทยขัดแย้งกับฉบับภาษาอังกฤษ **ให้ถือฉบับภาษาอังกฤษเป็นฉบับที่ใช้บังคับ** และไม่ว่าคำแปลในเอกสารนี้จะระบุไว้อย่างไร เงื่อนไขสัญญาอนุญาตทั้งหมดให้เป็นไปตามแฟ้ม `LICENSE` ฉบับภาษาอังกฤษเท่านั้น ข้อผิดพลาดในการแปลไม่ก่อให้เกิดสิทธิใด ๆ เพิ่มเติม

**เขียนสำหรับนักพัฒนาหรือทีมพัฒนาขนาดเล็กในมหาวิทยาลัยไทย ที่เพิ่งได้รับสิทธิ์เข้าถึง repository นี้และยังไม่เคยเห็น codebase มาก่อน**

เอกสารนี้ทำหน้าที่เป็น *เส้นทางนำอ่าน* เอกสารที่มีอยู่แล้ว ไม่ได้มาแทนที่เอกสารเหล่านั้น ตรงไหนที่ `docs/` อธิบายไว้ดีอยู่แล้ว คู่มือนี้จะชี้ทางไปที่นั่น พร้อมบอกว่าให้อ่านเพื่อหาอะไร

เขียนเมื่อ 2026-08-27 โดยอ้างอิง branch `main` ข้อความที่อาจคลาดเคลื่อนไปตามเวลาจะมี path ของไฟล์กำกับไว้ เพื่อให้ตรวจสอบซ้ำกับโค้ดชุดที่ได้รับมาจริงได้

## อ่านส่วนนี้ก่อน

**ข้อเท็จจริงข้อเดียวที่มีประโยชน์ที่สุดสำหรับมหาวิทยาลัยไทยที่จะนำแพลตฟอร์มนี้ไปใช้:** connector สี่ตัวอ่านจาก **ชุดข้อมูลมาตรฐานระดับชาติ MHESI UniCon** ซึ่งเป็นชุดข้อมูลเดียวกับที่สถาบันของคุณส่งให้กระทรวงอยู่แล้ว และเป็น schema เดียวกัน สี่ตัวนี้แทบจะนำไปใช้ได้ทันที เปลี่ยนแค่ host กับชื่อฐานข้อมูล อย่าไปแก้โครงสร้างตาราง

| Connector | ชุดข้อมูล | ข้อมูลที่บรรจุอยู่ |
|---|---|---|
| `unicon-ds1001` | DS1001 | ข้อมูลนักศึกษา หนึ่งแถวต่อ (นักศึกษา × ปีการศึกษา × ภาคการศึกษา) |
| `unicon-ds2001` | DS2001 | ทะเบียนหลักบุคลากร — ตำแหน่งทางวิชาการ สัญญาจ้าง แหล่งงบประมาณ สถานะการปฏิบัติงาน |
| `unicon-ds2003` | DS2003 | คุณวุฒิการศึกษาของบุคลากรทุกคน |
| `unicon-ds2004` | DS2004 | อาจารย์ประจำหลักสูตร (การเป็นกรรมการบริหารหลักสูตร) |

ตรวจสอบได้จากคอมเมนต์ส่วนหัวของ `apps/ingestion/src/connectors/sources/unicon-ds2001/connector.ts` — ทั้ง URL ของแหล่งข้อมูล การ projection คอลัมน์แบบเจาะจง และแนวปฏิบัติด้าน PDPA บันทึกไว้ในไฟล์นั้นครบ

ส่วนที่เป็นระบบเฉพาะของแต่ละสถาบัน — คลังข้อมูลสำนักทะเบียน ระบบบุคคล ระบบการเงิน ระบบประเมินการสอน คะแนนสมรรถนะดิจิทัล — สร้างขึ้นให้เข้ากับระบบของ มข. โดยเฉพาะ ต้องเขียนใหม่ให้ตรงกับระบบเทียบเท่าของแต่ละแห่ง [การเชื่อมต่อข้อมูล: สี่ระดับของภาระงานในการนำไปใช้](./data-tiers.md) จัดแหล่งข้อมูลทั้ง 39 รายการในแคตตาล็อกออกเป็นระดับตามปริมาณงานที่ต้องลงแรง

**ไม่จำเป็นต้องเขียน connector เหล่านั้นให้เสร็จก่อนจึงจะเห็นผล** ข้อมูล 16 ชุดอัปโหลดเป็นไฟล์ Excel ได้ที่ `/admin/data-setup` ได้แก่ คณะ ภาควิชา หลักสูตร จากนั้นจึงเป็นจำนวนนักศึกษา การเงิน ภาวะการมีงานทำของบัณฑิต รุ่นนักศึกษา การรับเข้า บุคลากร ค่าตอบแทน งบประมาณ ผลงานตีพิมพ์ รายวิชาที่เปิดสอน ทีมอาจารย์ประจำหลักสูตร และรายวิชาของหลักสูตร โดยไม่ต้องแก้โค้ดแม้แต่บรรทัดเดียว การอัปโหลดสร้างแถวข้อมูลที่ระบุแหล่งที่มาแบบเดียวกับที่ connector สร้าง หน้าจอทุกหน้าจึงปฏิบัติต่อทั้งสองแบบเหมือนกัน สถาบันส่วนใหญ่ควรเริ่มจากทางนี้ แล้วค่อยเขียน connector ภายหลังสำหรับข้อมูลที่พบว่าต้องอัปโหลดซ้ำบ่อย คู่มืออยู่ที่ [Importing from spreadsheets](../data-import.md)

**สามเรื่องที่ควรเข้าใจให้ขึ้นใจก่อนเริ่ม:**

- ระบบนี้เป็น **ระบบสนับสนุนการตัดสินใจที่มีเดิมพันสูง** — การปิดหลักสูตร การควบรวม ชีวิตความเป็นอยู่ของอาจารย์ codebase ออกแบบโดยมี provenance (การสืบค้นที่มาของตัวเลข) การบันทึก audit log การกำกับเวอร์ชันระเบียบวิธี และการเปิดเผยระดับความเชื่อมั่น เป็นแกนกลาง สิ่งเหล่านี้ไม่ใช่ของประดับ ถอดออกเมื่อไรก็เหลือแค่ dashboard ที่ไม่มีใครในสภามหาวิทยาลัยเชื่อถือ
- **ไม่มีทางลัดให้ใส่ข้อมูลปลอม เพราะเป็นนโยบาย** กติกาของโครงการคือแหล่งข้อมูลที่ยังต่อไม่ได้ต้อง *ว่างเปล่า* ไม่ใช่กรอกของปลอมแทน ส่วนที่ว่างจะขึ้นสถานะชัดเจนว่า "ไม่มีข้อมูล — ให้รัน connector ตัวนี้" ต้องห้ามใจไม่ให้เติมตัวเลขที่ดูสมเหตุสมผลลงไปแทน เพราะห่วงโซ่ provenance ทั้งเส้น (ดู [`realDataWhere()`](./traps.md#กับดักที่-2-realdatawhere--ส่วนที่ว่างเปล่าทั้งที่ฐานข้อมูลมีข้อมูล)) ออกแบบมาจับพฤติกรรมแบบนี้โดยเฉพาะ
- **โค้ดเผยแพร่ภายใต้ CC BY-NC-SA 4.0 ซึ่งมีภาระผูกพันจริง** — แสดงที่มา อนุญาตแบบเดียวกัน และไม่ใช้เพื่อการค้า — และ *ไม่ได้* อนุญาตให้ใช้เครื่องหมายการค้าของ มข. ไม่ครอบคลุมชุด dependency และไม่ครอบคลุมข้อมูลใด ๆ ของ มข. อ่านหัวข้อสัญญาอนุญาตด้านล่างให้จบก่อนนำโค้ดนี้ไปทำอะไรที่เป็นสาธารณะ

## สัญญาอนุญาต — CC BY-NC-SA 4.0

แฟ้ม `LICENSE` ใน repository นี้คือ **สัญญาอนุญาตครีเอทีฟคอมมอนส์ แบบแสดงที่มา-ไม่ใช้เพื่อการค้า-อนุญาตแบบเดียวกัน 4.0 นานาชาติ (CC BY-NC-SA 4.0)** โดยมีส่วนหัวของมหาวิทยาลัยขอนแก่นนำหน้าข้อความสัญญาอนุญาตฉบับเต็ม ลิขสิทธิ์ © พ.ศ. 2569 มหาวิทยาลัยขอนแก่น

ภาระผูกพันมีสี่ข้อ ถ้อยคำในสี่ข้อนี้ยกมาจากประกาศลิขสิทธิ์ฉบับภาษาไทยของ มข. ที่ `apps/web/app/(legal)/copyright/page.tsx` จึงเป็นภาษากฎหมายและเป็นทางการกว่าคำอธิบายรอบข้างโดยเจตนา:

- **การแสดงที่มา (BY)** — ท่านต้องระบุที่มาตามรูปแบบที่กำหนดไว้ในข้อ 11 ของประกาศดังกล่าว ระบุลิงก์ไปยังสัญญาอนุญาต และแจ้งว่าท่านได้ดัดแปลงงานหรือไม่ ต้องแสดงไว้ทั้งใน repository ในเอกสารประกอบ และในหน้าจอ "เกี่ยวกับ" หรือหน้าเครดิตที่ผู้ใช้มองเห็น
- **อนุญาตแบบเดียวกัน (SA)** — หากท่านปรับปรุง แปลง หรือต่อยอดจากงาน ท่านต้องเผยแพร่ส่วนที่ท่านสร้างสรรค์ขึ้นภายใต้สัญญาอนุญาต CC BY-NC-SA 4.0 หรือสัญญาอนุญาตที่ครีเอทีฟคอมมอนส์กำหนดให้ใช้ร่วมกันได้
- **ไม่ใช้เพื่อการค้า (NC)** — ท่านจะใช้งานนี้เพื่อวัตถุประสงค์ทางการค้ามิได้ อันหมายถึงการใช้ที่มุ่งประสงค์เป็นสำคัญต่อประโยชน์ทางการค้าหรือค่าตอบแทนอันเป็นตัวเงิน
- **คงข้อความแจ้งไว้ครบถ้วน** — ให้คงข้อความแสดงลิขสิทธิ์ ข้อความแสดงที่มา และข้อความแจ้งสัญญาอนุญาต ไว้ในทุกสิ่งที่เผยแพร่ต่อ

ส่วนหัวของแฟ้ม `LICENSE` มีข้อความแสดงที่มาแบบสำเร็จรูปให้คัดลอกไปใช้อยู่แล้ว ใช้ข้อความนั้น อย่าคิดถ้อยคำขึ้นเอง

**สามสิ่งที่สัญญาอนุญาตนี้ไม่ได้ให้ และแต่ละข้อจะเล่นงานใครสักคนในทีมแน่นอน:**

- **เครื่องหมายของ มข. ไม่ได้อยู่ภายใต้สัญญาอนุญาต** ทั้ง "Khon Kaen University", "มหาวิทยาลัยขอนแก่น", "KKU", ตราสัญลักษณ์ประจำมหาวิทยาลัย และแฟ้มโลโก้ใน `apps/web/public/brand/` สงวนไว้โดยชัดแจ้ง สัญญาอนุญาตครีเอทีฟคอมมอนส์ให้สิทธิเฉพาะในทางลิขสิทธิ์ และข้อ 2(b)(2) ระบุเรื่องนี้ไว้ตรง ๆ ระบบที่คุณนำไปติดตั้งใช้งานเองต้องถอดเครื่องหมายเหล่านี้ออกหรือเปลี่ยนเป็นของสถาบันตนเอง [การปรับแบรนด์และ UI](../guides/rebrand.md) คือรายการตรวจสอบ และมีไฟล์ประมาณ 101 ไฟล์ใต้ `apps/web` ที่เอ่ยชื่อ มข.
- **ชุด dependency ไม่ได้อยู่ภายใต้สัญญาอนุญาตของ มข.** `node_modules` อิมเมจคอนเทนเนอร์ฐาน และฟอนต์ ต่างมีข้อกำหนดของตัวเอง ฟอนต์ TH Sarabun New เป็นกรณีที่ชัดที่สุด — ไม่ได้อยู่ใน repository และมีเงื่อนไขของตัวเอง ตรวจสอบให้ครบก่อนเผยแพร่ต่อ
- **ไม่มีข้อมูลของ มข. มาพร้อมกับโค้ด** ทั้งฐานข้อมูลหลักสูตร 297 หลักสูตร ระเบียนนักศึกษาและบุคลากร และผลการประเมินทุกอย่างที่คำนวณจากข้อมูลเหล่านั้น อยู่นอกขอบเขตการเผยแพร่ครั้งนี้ทั้งหมด [ขอบเขตและภาระงาน](./scope-and-effort.md#สิ่งที่จะไม่ได้รับ) คือรายการฉบับเต็ม

**เรื่อง "ไม่ใช้เพื่อการค้า" อ่านตรงนี้ก่อนจะเดาเอง** คำนี้ไม่ได้นิยามละเอียดพอสำหรับบริบทมหาวิทยาลัย และมหาวิทยาลัยก็ทำหลายอย่างที่คาบเส้นนั้นอยู่ เช่น การดำเนินงานที่ใช้เงินค่าธรรมเนียมการศึกษา งานวิจัยตามสัญญาจ้าง หลักสูตรผู้บริหาร หลักสูตรระยะสั้นที่เก็บค่าลงทะเบียน และบริษัท spin-off ตอนนี้ มข. ยังไม่ได้เผยแพร่การตีความคำนี้สำหรับงานชิ้นนี้ **ถ้าการใช้งานที่ตั้งใจไว้อยู่ใกล้เส้นนั้น ให้ขอคำยืนยันเป็นลายลักษณ์อักษรจากผู้ประสานงานด้านสัญญาอนุญาตของ มข. ก่อนลงแรงต่อยอด** ชื่อผู้ประสานงานอยู่ท้ายแฟ้ม `LICENSE`

**สำหรับนิติกรของทั้งสองฝ่าย** CC BY-NC-SA เป็นสัญญาอนุญาตสำหรับ *เนื้อหา* ที่ถูกเอามาใช้กับ *ซอฟต์แวร์* ซึ่งครีเอทีฟคอมมอนส์เองก็ไม่แนะนำให้ทำ ผลที่ตามมาคือ ไม่มีการให้สิทธิบัตร ไม่มีภาระผูกพันเรื่องการเปิดเผยซอร์สโค้ดที่สอดคล้อง ขอบเขตของเงื่อนไขอนุญาตแบบเดียวกันเมื่อมีการ link ยังไม่ชัด บวกกับความคลุมเครือของคำว่าไม่ใช้เพื่อการค้าข้างต้น ทั้งหมดนี้พร้อมแนวทางบรรเทาความเสี่ยงอยู่ใน [`docs/licensing.md`](../../licensing.md) เอกสารฉบับนั้นเป็นคำแนะนำเชิงวิศวกรรม ไม่ใช่ความเห็นทางกฎหมาย ใช้เป็นเอกสารสรุปประเด็นส่งให้ที่ปรึกษากฎหมาย ไม่ใช่คำตอบสุดท้าย

| 6 | Competitive Benchmarking | การเทียบเคียงคู่เทียบ และการหาช่องว่างที่ยังไม่มีใครทำ |

| 8 | Decision Workspace | บันทึกมติ การอนุมัติ และการทบทวนผลลัพธ์ |

**ทุกหน้าจอเชิงวิเคราะห์ทำงานได้ทั้งสี่ระดับขอบเขต** — มหาวิทยาลัย คณะ ภาควิชา หลักสูตร — โดยเก็บขอบเขตไว้ใน URL (`?scope=faculty&scopeId=<id>`) ทุกมุมมองจึงแชร์ต่อได้ ข้อนี้เป็นกฎทางสถาปัตยกรรม ไม่ใช่ธรรมเนียมที่ยืดหยุ่นได้ ดู `CLAUDE.md` หัวข้อ *Multi-level analytical scope*

**สแตกเทคโนโลยี** ตรวจสอบเทียบกับ `package.json` และ manifest ของแต่ละ workspace แล้ว:

| ชั้น | สิ่งที่เลือกใช้ |
|---|---|
| Frontend | Next.js 14 App Router, TypeScript strict (ห้าม `any`), Tailwind, UI ที่ต่อยอดจาก shadcn, Recharts + SVG เขียนเอง |
| Backend | NestJS |
| ฐานข้อมูล | PostgreSQL 16 พร้อม `postgis`, `pgvector`, `pg_trgm`, `btree_gin` |
| ORM | Prisma (มี migration 106 ตัว ณ วันที่ส่งมอบ) |
| Cache / queue | Redis + BullMQ |
| Object storage | MinIO (เข้ากันได้กับ S3) |
| การออก PDF | Gotenberg (Chromium แบบ headless) พร้อมฟอนต์ TH Sarabun New ฝังในอิมเมจ |
| Auth | `next-auth` v5, OIDC SSO ส่วน local credentials **ใช้ได้เฉพาะ dev และ fail ทันทีใน production** |
| AI | ชั้นนามธรรม `AiService` ครอบ Google Gemini / Anthropic Claude |
| การทดสอบ | Vitest (118 ไฟล์ทดสอบ ประมาณ 1,400 เคส `it()`/`test()`) และ Playwright สำหรับ e2e |
| Monorepo | pnpm workspaces — `apps/{web,api,ingestion}`, `packages/{shared,db,ui,design,pdf-templates}` |

รายละเอียดสถาปัตยกรรมที่ลึกกว่าตารางนี้อยู่ใน `docs/architecture.md` ส่วนวิธีที่โมดูลการให้คะแนนต่าง ๆ ประกอบกัน อ่าน `docs/evaluation-pipeline.md` ซึ่งเป็นแผนที่ข้ามโมดูล และเป็นเอกสารที่มีประโยชน์ที่สุดก่อนจะแก้อะไรก็ตามที่แตะเกินหนึ่งโมดูล
