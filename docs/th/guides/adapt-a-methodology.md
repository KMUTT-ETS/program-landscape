# การปรับระเบียบวิธีให้เข้ากับสถาบันของคุณ

> **English:** [English version](../../guides/adapt-a-methodology.md)

ทุกคะแนนที่แพลตฟอร์มผลิตออกมา คำนวณด้วยฟังก์ชันที่กำกับเวอร์ชันไว้ชัดเจนใน `packages/db/src/` และมีเอกสารคู่กันใต้ `docs/methodologies/`

## กฎสามข้อสำหรับการเปลี่ยนระเบียบวิธี

1. **เปลี่ยนเวอร์ชันเสมอ** เวอร์ชันระเบียบวิธี (สำหรับคะแนนสุขภาพคือ `health-score.v5.6`) ถูกประทับลงทุกแถวคะแนน สำหรับคะแนนสุขภาพ ท่านเปลี่ยนผ่านเลขรุ่นของสถาบันท่านเอง ดูหัวข้อ "ประทับเวอร์ชันของสถาบันท่านเอง" ด้านล่าง การเปลี่ยนสูตรโดยไม่ขยับเวอร์ชันทำให้การเปรียบเทียบย้อนหลังผิดแบบเงียบ ๆ และทำลายร่องรอยการตรวจสอบที่ทำให้กรรมการสภามหาวิทยาลัยถามได้ว่า "ทำไมคะแนนหลักสูตรนี้เปลี่ยนไป"
2. **อัปเดตเอกสารใน commit เดียวกัน** เอกสารใต้ `docs/methodologies/` คือฉบับที่ใช้อ้างอิงว่าตัวเลขหมายถึงอะไร เอกสารที่คลาดเคลื่อนแย่กว่าไม่มีเอกสารเลย
3. **ค่าว่างไม่ใช่ศูนย์** กฎรากฐานของคะแนนสุขภาพ: ตัววัดที่ขาดหายต้อง **ถูกตัดออกจากการเฉลี่ย** ห้ามแทนด้วย 0 หรือ 50 ทุกคะแนนพก `dataCompletenessPct` มาด้วย และหน้าจอแสดงค่าที่ขาดหายเป็น `—` อย่าไป "แก้" ข้อนี้ การแทนด้วยศูนย์คือการลงโทษหลักสูตรเพราะช่องว่างข้อมูลของคุณเอง ซึ่งเป็นรูปแบบความล้มเหลวที่ทำลายความเชื่อถือของสภามหาวิทยาลัยได้ตรงที่สุด

## จุดที่น้ำหนักของคุณจะต่างออกไป

คะแนนสุขภาพของ มข. ประกอบด้วยห้ามิติ (ความน่าสนใจ การเงิน ขีดความสามารถ ผลลัพธ์ ความสอดคล้อง) โดยแต่ละมิติมีตัวขับเคลื่อนย่อยอยู่ข้างใน บางตัวถ่วงน้ำหนักตามวิจารณญาณเชิงกลยุทธ์ของ มข. อย่างชัดเจน เช่น ตัวขับเคลื่อนด้านอุปสงค์ที่ถ่วงน้ำหนักเพื่อสะท้อน "การเคลื่อนไปสู่การพัฒนากำลังคนแบบไม่รับปริญญา ซึ่งบีบหลักสูตรระดับบัณฑิตศึกษา" สิ่งเหล่านี้เป็น **จุดยืนของสภามหาวิทยาลัยขอนแก่น ไม่ใช่สัจธรรมสากล** และควรเผื่อใจว่าจะต้องเปลี่ยน

แพตเทิร์นที่ปลอดภัยคือเก็บการเปลี่ยน *ค่าพารามิเตอร์* ของคะแนนสุขภาพไว้ในไฟล์เดียว คือ `packages/db/src/health-score/tuning.ts` แล้วประทับด้วยเวอร์ชันของท่านเอง วิธีนี้ยังรับ merge การเปลี่ยน *โครงสร้าง* ของสูตรจาก upstream ได้ราบรื่น เพราะ upstream แทบไม่แตะบรรทัดที่ท่านแก้

**ก่อนเปลี่ยนอะไรที่ข้ามโมดูล ให้อ่าน `docs/evaluation-pipeline.md`** เอกสารนั้นทำแผนที่ว่าคะแนนสุขภาพ วงจรชีวิต ความเสี่ยง KKU matrix และการจัดกลุ่มแบบ BCG เกี่ยวพันกันอย่างไร ผ่าน prompt ของ AI 22 ตัวและชุด cross-join การเปลี่ยนน้ำหนักตัวเดียวโดด ๆ อาจดันหลักสูตรข้ามเส้นแบ่งควอดรันต์ BCG ไปโดยไม่ได้ตั้งใจ

## จะแก้อะไร ต้องแก้ที่ไหน

| สิ่งที่ต้องการเปลี่ยน | แก้ที่ | ต้องเปลี่ยนเวอร์ชันไหม |
|---|---|---|
| เกณฑ์รับนักศึกษาขั้นต่ำรายระดับหลักสูตร | ข้อมูลองค์กร (หน้าผู้ดูแลระบบ) | ไม่ต้อง เป็นนโยบาย ไม่ใช่สูตร |
| ภูมิภาคของสถาบัน (ใช้กับความทนทานด้านประชากร) | ข้อมูลองค์กร (หน้าผู้ดูแลระบบ) | ไม่ต้อง |
| กลุ่มรูปแบบการสอนของคณะ สำหรับสัดส่วนนักศึกษาต่ออาจารย์ | การตั้งค่าคณะ (หน้าผู้ดูแลระบบ) | ไม่ต้อง |
| เกณฑ์ จุดบนเส้นโค้ง เป้าหมาย หรือน้ำหนัก (เช่น ขอบของกลุ่มสัดส่วนนักศึกษาต่ออาจารย์ เป้ารายได้รายระดับ กลุ่มอาชีพยุทธศาสตร์ สัดส่วนในประเทศ 75 : ต่างประเทศ 25) | `packages/db/src/health-score/tuning.ts` | ต้อง |
| วิธีคำนวณตัวขับเคลื่อน | ไฟล์ของมิตินั้นใน `packages/db/src/health-score/` (`attractiveness.ts`, `financial.ts`, `capability.ts`, `outcomes.ts`, `relevance.ts`) แก้ทั้งตัวคำนวณระดับหลักสูตร **และ** ตัวคำนวณระดับขอบเขต | ต้อง |
| เพิ่มหรือตัดตัวขับเคลื่อน | ไฟล์ของมิตินั้น **และ** `DIMENSION_DRIVERS` ใน `drivers.ts` | ต้อง |

`packages/db/src/health-score/README.md` บอกว่าตัวขับเคลื่อนแต่ละตัวคำนวณในไฟล์ใด ค่าทุกค่าใน `tuning.ts` ตั้งชื่อตามป้ายตัวขับเคลื่อนที่แสดงใน tooltip ของคะแนนในระบบ การค้นด้วยป้ายนั้นจึงพบทั้งค่าและโค้ด

## ประทับเวอร์ชันของสถาบันท่านเอง

upstream (มข.) เป็นเจ้าของเลข `health-score.vX.Y` สถาบันของท่านไม่ขยับเลขนั้น แต่ตั้งเลขรุ่นของตนเองใน `tuning.ts`:

```ts
export const INSTITUTION_REVISION: string | null = 'kmutt.1';
```

ทุกคะแนนจะถูกประทับเป็น `health-score.v5.6+kmutt.1` ตัวเลขที่คำนวณด้วยค่าของท่านจึงไม่มีทางถูกเข้าใจผิดว่าเป็นตัวเลขของ มข. และเมื่อ upstream ขยับเวอร์ชันในภายหลังก็จะเห็นเป็น `health-score.v5.7+kmutt.1` ให้ขยับเลขรุ่นของท่าน (`kmutt.2`, `kmutt.3` …) ทุกครั้งที่เปลี่ยนค่าหรือตรรกะ

การทดสอบ `packages/db/test/health-score-tuning-pin.test.ts` บังคับกฎนี้ จะล้มเมื่อ `tuning.ts` เปลี่ยนแต่เวอร์ชันไม่เปลี่ยน และพิมพ์ลายนิ้วมือ (fingerprint) ที่ต้องปักหมุดให้เวอร์ชันใหม่:

```bash
pnpm --filter @kku/db test health-score-tuning-pin
```

เพิ่มบรรทัดที่พิมพ์ออกมาลงใน `PINNED` ในไฟล์นั้น และเก็บบรรทัดเก่าไว้ เพราะเป็นบันทึกว่าเวอร์ชันที่เผยแพร่แต่ละรุ่นใช้ค่าอะไร การทดสอบนี้เห็นเฉพาะตัวเลข การเปลี่ยนตรรกะของตัวคำนวณก็ต้องขยับเลขรุ่นเช่นกัน และถ้าลืม จะมีเพียงการรีวิวโค้ดที่จับได้

## การจัดสรรต้นทุนยังไม่เสร็จ — ที่ มข. ก็เช่นกัน

`docs/methodologies/cost-allocation.md` ยังเป็น **ร่าง v0** รอความเห็นชอบจากคณะกรรมการการเงิน เอกสารนี้วางกลุ่มต้นทุนไว้ห้ากลุ่มพร้อมสูตรแบบอิงกิจกรรม และ connector ก็ป้อนข้อมูลดิบเข้ามาให้แล้ว แต่ยังไม่มีตัวเลขต้นทุนรายหลักสูตรตัวไหนที่เสนอต่อสภามหาวิทยาลัยได้ ถ้าการวิเคราะห์ความยั่งยืนทางการเงินเป็นเรื่องเร่งด่วนของคุณ นี่คืองานที่ยังไม่เสร็จจริง ๆ ที่รับสืบทอดมา ไม่ใช่แค่ขั้นตอนการตั้งค่า
