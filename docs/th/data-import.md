# นำเข้าข้อมูลของสถาบันจากสเปรดชีต

> **English:** [`data-import.md`](../data-import.md)

โดยปกติ Program Landscape อ่านข้อมูลของสถาบันผ่าน connector ซึ่งเป็นโค้ดที่เชื่อมต่อกับฐานข้อมูลของงานทะเบียน งานบุคคล หรืองานการเงินโดยตรง หากท่านไม่มีสิทธิ์เข้าถึงระบบเหล่านั้น หรือข้อมูลของท่านอยู่ในสเปรดชีตอยู่แล้ว ท่านอัปโหลดข้อมูลแทนได้ โดยไม่ต้องแก้โค้ด

หน้านี้เขียนสำหรับผู้ที่ทำหน้าที่อัปโหลดข้อมูล

โหลดจากบนลงล่าง สามชุดแรกเป็นโครงหลักที่ทุกอย่างอ้างอิงด้วยรหัส **Staff** ต้องมาก่อน **Publications**, **Programme Teaching Staff** และ **External Grant Team** ซึ่งระบุตัวบุคคลด้วยรหัสพนักงาน นอกจากนั้น แผ่นงานหนึ่งต้องการเพียงแผ่นงานที่ระบุในแถวของตนด้านบน เพราะอ้างอิงรหัสของแผ่นงานเหล่านั้น และไฟล์ที่ระบุรหัสซึ่งยังไม่มีอยู่จะถูกปฏิเสธ

**คอลัมน์ของ Faculties** Faculty Code, Name (Thai) และ Name (English) เป็นคอลัมน์ที่จำเป็น Kind ไม่บังคับ (ค่าเริ่มต้นคือ ACADEMIC) **Teaching Mode** ไม่บังคับ และกำหนดอัตราส่วนนักศึกษาต่ออาจารย์ที่ใช้ประเมินคะแนน Capability ของคณะ ได้แก่ *Clinical* (ฝึกปฏิบัติภายใต้การดูแลผู้ป่วย เข้มงวดที่สุด), *Lab-based* (วิทยาศาสตร์และวิศวกรรมที่เน้นห้องปฏิบัติการ), *Studio* (การสอนรายบุคคลด้านการออกแบบหรือศิลปะ), *Professional* (หลักสูตรวิชาชีพที่เรียนเป็นรุ่น) หรือ *Humanities* (มนุษยศาสตร์ สังคมศาสตร์ และศึกษาศาสตร์ที่เน้นการบรรยาย ผ่อนปรนที่สุด) หากปล่อยว่าง คณะใหม่จะถูกให้คะแนนแบบ Professional และเมื่ออัปโหลดซ้ำ ค่าว่างจะคงค่าที่เก็บไว้เดิม

**สถาบันไทย: สะกดชื่อคณะให้ตรงกับที่ TCAS ใช้** connector ของ TCAS จะเชื่อมตัวเลขการรับสมัครระดับชาติ (mytcas.com) กับหลักสูตรได้ ก็ต่อเมื่อชื่อภาษาไทยของคณะตรงกับการสะกดของ TCAS ทุกตัวอักษร เช่น `คณะวิศวกรรมศาสตร์` โดยไม่มีส่วนต่อท้ายที่เป็นวิทยาเขตหรือชื่อมหาวิทยาลัย ชื่ออย่าง `คณะวิศวกรรมศาสตร์ (วิทยาเขตหลัก)` จะไม่เชื่อมกับอะไรเลย และส่วน Admissions ของทุกหน้าหลักสูตรจะว่างเปล่า

**อย่าข้าม Programme Teaching Staff** แผ่นงานนี้เป็นตารางเชื่อมโยง ไม่ใช่ชุดตัวเลข จึงมักถูกเลื่อนไปทำทีหลัง และข้อมูลสามอย่างที่ท่านอัปโหลดแล้วจะเงียบอยู่จนกว่าจะมีแผ่นงานนี้ ผลงานตีพิมพ์เชื่อมกับ *บุคคล* และบุคคลจะเชื่อมถึง *หลักสูตร* ได้ผ่านแผ่นงานนี้เท่านั้น ถ้าไม่มี หน้าหลักสูตรจะไม่แสดงทีมผู้สอน ตัวเลขอัตรากำลังและความอาวุโสจะว่าง ข้อมูลงานวิจัยที่ท่านอัปโหลดจะไม่มีผลต่อหลักสูตรใดเลย และส่วน Capability ของคะแนนสุขภาพ (health score) ของแต่ละหลักสูตรจะคำนวณไม่ได้เลย

มีสองอย่างที่ตั้งใจไม่ให้มี: **ตัวเลขต้นทุน** อัปโหลดไม่ได้ เพราะต้นทุนของหลักสูตรเป็นการจัดสรรที่สถาบันของท่านต้องปกป้องได้ จึงสร้างจากวิธีวิทยาการจัดสรรต้นทุน (cost-allocation methodology) โดยใช้ข้อมูลบุคลากรและงบประมาณ และการอัปโหลดจะไม่แตะต้องต้นทุน **ข้อมูลประชากรศาสตร์ของนักศึกษา** อัปโหลดไม่ได้เช่นกัน เพราะปัจจุบันไม่มีส่วนใดของแอปอ่านข้อมูลนี้ หากมีเทมเพลต จะเป็นการขอให้ท่านทำงานที่ไม่มีหน้าจอใดแสดงผล

อีกบางอย่างอยู่นอกขอบเขตโดยเจตนา และบันทึกไว้ในเอกสารออกแบบใต้ `docs/superpowers/specs/` ได้แก่ การประเมินการสอนรายอาจารย์ (แผ่นงาน Course Evaluations เป็นระดับรายวิชาเท่านั้น) และรายชื่อผู้สอนต่อกลุ่มเรียน เพราะอ้างอิงที่อยู่อีเมลส่วนบุคคล โปรดสังเกตว่าผู้สอนต่อกลุ่มเรียนต่างจาก **Programme Teaching Staff** ข้างต้น อย่างแรกบอกว่าใครยืนสอนในชั้นเรียนหนึ่ง อย่างหลังบอกว่าทีมผู้สอนของหลักสูตรคือใคร และนำเข้าได้เฉพาะอย่างหลัง

## Class Offerings แทนที่ทั้งภาคการศึกษา ส่วนที่เหลือใช้การผสาน

นี่เป็นชุดข้อมูลเดียวที่ทำงานต่างออกไป ควรทำความเข้าใจก่อนอัปโหลดครั้งแรก

แผ่นงานอื่นทุกแผ่น **ผสาน (merge)** คืออัปเดตแถวที่ระบุ เพิ่มแถวใหม่ และปล่อยส่วนที่เหลือไว้ แต่ Class Offerings **แทนที่ภาคการศึกษาที่ไฟล์ครอบคลุม** อัปโหลดไฟล์ภาคเรียนที่ 1 ปี 2024 แล้วกลุ่มเรียนของภาคเรียนที่ 1 ปี 2024 ที่เก็บไว้แล้วทั้งหมดจะถูกลบก่อน จากนั้นจึงใส่แถวของไฟล์

ที่เป็นเช่นนี้โดยเจตนา เพราะข้อมูลตารางสอนที่ส่งออกมาบอกว่า *อะไรมีอยู่* ไม่ได้บอกว่า *อะไรเปลี่ยน* กลุ่มเรียนที่ถูกยกเลิกหลังการอัปโหลดครั้งก่อนจะหายไปจากไฟล์ใหม่ และถ้าใช้การผสานก็จะค้างอยู่ในระบบตลอดไป

ผลที่ตามมามีสามข้อ

- **หนึ่งไฟล์ต่อหนึ่งภาคการศึกษา** และทุกแถวในไฟล์ต้องเป็นภาคการศึกษาเดียวกัน ไฟล์ที่ปนสองภาคการศึกษาจะถูกปฏิเสธ พร้อมระบุแถวที่ไม่ตรงกัน
- **ไฟล์ต้องครบสำหรับภาคการศึกษานั้น** การอัปโหลดข้อมูลส่งออกที่ไม่ครบจะลบกลุ่มเรียนที่ไฟล์ไม่มี
- **ภาคการศึกษาอื่นไม่ถูกแตะต้อง** การโหลดภาคเรียนที่ 2 ปี 2024 ไม่กระทบภาคเรียนที่ 1

## Programme course lists — ทางสำรองเมื่ออ่าน PDF ไม่ได้

pipeline ของหลักสูตรสร้างรายวิชาของแต่ละหลักสูตรจาก PDF หลักสูตร (phase 2b) ตัวอ่านคาดหวังรหัสรูปแบบเดียว ดังนั้น PDF ที่มีรหัสอย่าง `MEE 221` ไฟล์สแกน หรือรูปแบบหน้าที่ผิดปกติ อาจให้ผลเป็นไม่มีรายวิชาเลย และส่วน overlap ของหลักสูตร การปรับปรุงหลักสูตร (curriculum revision) และส่วนรายวิชาของ Deep-Dive จะว่างเปล่า แผ่นงานนี้เป็นทางสำรอง คือท่านเป็นผู้ให้รายวิชาเอง

คอลัมน์: **Programme Code** และ **Course Code** (จำเป็น), **Course Name (Thai)**, **Course Name (English)**, **Credits** (0 ถึง 99) และ **Category** Category รับป้ายภาษาอังกฤษ ป้ายภาษาไทย หรือโทเค็นที่เก็บไว้ (ไม่สนตัวพิมพ์เล็กใหญ่): General education / หมวดวิชาศึกษาทั่วไป, Core / วิชาแกน, Major required / วิชาเฉพาะบังคับ, Major elective / วิชาเฉพาะเลือก, Free elective / หมวดวิชาเลือกเสรี, Thesis / project / วิทยานิพนธ์/โครงงาน, Unknown / ไม่ระบุ ค่าว่างจะเก็บเป็น Unknown ไม่มีการเดา

**ระบุรายวิชาศึกษาทั่วไปเป็น General education** overlap ของหลักสูตรถือว่า Unknown เป็นรายวิชาเอก กฎสำรองตามรหัสนำหน้าของระบบรู้จักเฉพาะรหัสนำหน้า GE, LI และ 00 ซึ่งเป็นของ KKU ดังนั้นรายวิชาศึกษาทั่วไปของท่านจะถูกนับเป็นรายวิชาเอก (และทำให้ overlap ระหว่างหลักสูตรสูงเกินจริง) เว้นแต่ Category จะระบุไว้เป็นอย่างอื่น

พฤติกรรม:

- **การอัปโหลดหลักสูตรหนึ่งจะแทนที่รายวิชาทั้งหมดของหลักสูตรนั้น** รวมถึงแถวที่ตัวสกัดจาก PDF เขียนไว้ หลักสูตรที่ไฟล์ไม่ได้ระบุจะไม่ถูกแตะต้อง สองแถวที่มีรหัสเป็นค่าเดียวกันหลังปรับรูปแบบ (ตัวพิมพ์ ช่องว่าง) จะถูกปฏิเสธ พร้อมระบุทั้งสองแถว
- **การอัปโหลดมีลำดับความสำคัญเหนือ PDF** เมื่อหลักสูตรมีรายวิชาที่นำเข้าแล้ว phase 2b จะข้ามหลักสูตรนั้น (`course list supplied by spreadsheet import — not re-extracting`) และสคริปต์ materialise จะข้ามแม้ใช้ `--force` ไม่มีอะไรสกัดซ้ำทับรายวิชาของท่าน
- **Start over เป็นทางเดียวที่จะกลับไปใช้ PDF** การ start over ชุดข้อมูลจะลบรายวิชาที่นำเข้าทั้งหมด และคืนหลักสูตรเหล่านั้นให้ phase 2b ไม่มีการปล่อยทีละหลักสูตร มีวิธีเลี่ยงสองแบบ หากต้องการรีเฟรชรายวิชาของหลักสูตรเดียว (เช่น หลังปรับปรุงหลักสูตรฉบับใหม่ โดยแถวที่นำเข้าจะคงฉบับปรับปรุงที่ใช้ตอนโหลด) ให้อัปโหลดหลักสูตรนั้นอีกครั้ง หากต้องการคืนหลักสูตรเดียวให้ PDF ให้ดาวน์โหลดแฟ้มที่เก็บไว้ ทำ start over แล้วอัปโหลดส่วนที่เหลืออีกครั้ง
- **shrink guard เปรียบเทียบเฉพาะกับแถวที่การนำเข้าครั้งก่อนเขียนไว้** สำหรับหลักสูตรเหล่านั้น ดังนั้นการอัปโหลดครั้งแรกจะไม่ถูกปฏิเสธเพราะแทนที่รายการที่ตัวสกัดเก็บมาเกิน
- **pipeline รันชนกับการอัปโหลด** หาก pipeline กำลังเขียนรายวิชาที่สกัดได้ของหลักสูตรหนึ่งในจังหวะเดียวกับที่การอัปโหลดของหลักสูตรนั้น commit การอัปโหลดอาจถูกเขียนทับ ในกรณีนั้นให้อัปโหลดหลักสูตรนั้นอีกครั้ง (ช่วงเวลาเสี่ยงคือคำสั่งฐานข้อมูลเดียว)
- แถวที่นำเข้าจะถูกประทับ `xlsx-import.v1` พร้อมการรัน ingestion ของการอัปโหลดนั้น และฉบับปรับปรุงที่ใช้งานอยู่ของหลักสูตร

สิ่งที่ควรรู้เกี่ยวกับส่วนที่อ่านรายวิชา:

- การ์ดรายวิชาของ Deep-Dive แสดงเฉพาะรายวิชาที่ปรากฏใน Class Offerings พร้อมกลุ่มเรียนที่มีเกรดและใช้รหัสวิชาเดียวกัน จึงต้องอัปโหลด Class Offerings ที่รหัสตรงกัน การ์ดจึงจะมีข้อมูล
- การปรับปรุงหลักสูตรอ่านคำอธิบายรายวิชาจาก AI digest ไม่ใช่จากตารางนี้ และแถวหมวด Unknown จะไม่ถูกเสนอให้เลื่อนระดับ (promotion candidate) การตรวจรหัสรายวิชาในข้อความ (`PROSE_COURSE_CODE_RE` ตัวเลขห้าหรือหกหลัก) พลาดรหัส 3 หลัก ซึ่งกระทบเพียงตัวนับเพื่อการวินิจฉัย
- ตั้งใจ **ไม่มีคอลัมน์คำอธิบาย** เพราะการปรับปรุงหลักสูตรจะไม่สนใจคำอธิบายนั้น และการเตรียมข้อมูล overlap จะเขียนทับคำอธิบายเมื่อใดก็ตามที่ digest ที่อนุมัติแล้วระบุรหัสเดียวกัน

## Course Evaluations — มาตรวัด Student Satisfaction

หนึ่งแถวต่อหนึ่งกลุ่มเรียนต่อหนึ่งภาคการศึกษา: **ค่าเฉลี่ยของมาตรา 1–5** ที่นักศึกษาให้รายวิชาโดยรวม และจำนวนผู้ตอบ ใช้เป็นมาตรวัด Student Satisfaction ในคะแนน Outcomes ของแต่ละหลักสูตร ไม่มีแถวรายอาจารย์หรือรายคำถาม และไม่มีสิ่งใดในแผ่นงานที่ระบุตัวผู้สอน

คอลัมน์: **Course Code**, **Academic Year**, **Semester** (1, 2 หรือ 3) และ **Average Rating** (1 ถึง 5 จำเป็น), **Respondents** (จำเป็น), **Section** (เว้นว่างสำหรับรายวิชาที่มีกลุ่มเดียว), **Faculty Code**, **Course Name (Thai)** และ **Course Name (English)**

- **โหลด programme course lists ก่อน** มาตรวัดนี้เชื่อมรหัสรายวิชากับรายวิชาของหลักสูตร รายวิชาที่ไม่อยู่ในรายการของหลักสูตรใดเลยจะไม่นับ ไม่ว่าจะอัปโหลดกี่แถวก็ตาม ช่องว่างและตัวพิมพ์ในรหัสจะถูกละเลย
- **Academic Year เป็นปีคริสต์ศักราช** (2025) ระบบเก็บเป็นพุทธศักราช (2568) ดังนั้นมุมมองข้อมูลของผู้ดูแลระบบจะแสดงปีบวก 543 ปีพุทธศักราชที่พิมพ์ในช่องนี้จะถูกปฏิเสธ
- **Average Rating ไม่ใช่เปอร์เซ็นต์** 4.25 ถูกต้อง 85 หรือ 0.85 จะถูกปฏิเสธ มาตรวัดถ่วงน้ำหนักแต่ละแถวด้วย Respondents และนับเฉพาะภาคเรียนที่ 1 และ 2 แถวภาคฤดูร้อนจึงถูกเก็บไว้แต่ไม่ทำให้คะแนนเปลี่ยน
- **ผู้ตอบอย่างน้อยห้าคนต่อแถว** แถวที่ต่ำกว่านี้จะถูกปฏิเสธ และข้อความจะไม่แสดงคะแนนซ้ำ
- **Faculty Code ไม่บังคับ แต่ควรกรอก** มุมมองความพึงพอใจระดับคณะจัดกลุ่มตามรหัสนี้ แถวที่ไม่มีรหัสจะหายไปจากมุมมองนั้น
- อัปโหลดรายวิชา ภาคการศึกษา และกลุ่มเรียนเดิมอีกครั้งจะอัปเดตแถวนั้น
- **แถวเป็นระดับรายวิชา** แต่ละแถวเก็บเป็นแถว OVERALL หนึ่งแถวของกลุ่มเรียน โดยไม่แยกรายคำถาม แถวที่นำเข้านับในมาตรวัด Student Satisfaction แต่ไม่รวมในหลักฐานธีม AUNQA และมุมมอง teaching-talent ซึ่งต้องใช้รายละเอียดรายคำถาม

## External grants — โครงการและทีม

สองแผ่นงานป้อนข้อมูลให้แดชบอร์ดทุนของบุคลากร (Staff grants) และ **grant award** ในคะแนน Financial ของหลักสูตร (สูงสุด +10 คะแนน ไม่เคยหักคะแนน) ให้โหลดโครงการก่อน แล้วจึงโหลดทีม

**External Grants**: หนึ่งแถวต่อหนึ่งโครงการ คอลัมน์: **Project Code** (รหัสของท่านเอง ไม่ซ้ำในไฟล์ จำเป็น), **Title (Thai)** (จำเป็น), **Title (English)**, **Type** (Research, Academic service, Consulting หรือ Other), **Fiscal Year** (จำเป็น), **Budget (THB)**, **Funder** และ **Lead Faculty Code** (จำเป็น มาจากแผ่นงาน Faculties)

**External Grant Team**: หนึ่งแถวต่อหนึ่งคนต่อหนึ่งโครงการ คอลัมน์: **Project Code** (ต้องมีในแผ่นงาน External Grants), **Employee Code** (ต้องเป็นบุคลากรจากแผ่นงาน Staff รหัสที่ไม่ตรงกับใครจะถูกปฏิเสธ พร้อมระบุแถว) และ **Role** (Lead หรือ Co-investigator)

- **Fiscal Year เป็นปีคริสต์ศักราช** ปีงบประมาณของไทยเริ่มวันที่ 1 ตุลาคมของปีปฏิทินก่อนหน้า ปีงบประมาณ 2025 จึงเริ่มวันที่ 1 ตุลาคม 2024 ระบบเก็บเป็นพุทธศักราช (บวก 543) ปีพุทธศักราชจะถูกปฏิเสธ
- **award อ่านปีงบประมาณที่สมบูรณ์ล่าสุดสามปี** โดยนับแต่ละโครงการหนึ่งครั้งด้วยงบประมาณทั้งโครงการ สำหรับโครงการที่มีบุคลากรสายสอนที่ยังปฏิบัติงานของหลักสูตรนั้นร่วมอยู่ งบประมาณไม่เคยถูกแบ่งระหว่างบุคคล โครงการที่ไม่มี Budget จะไม่นับ
- **ระบุบุคลากรด้วยรหัสพนักงานเท่านั้น** ไม่มีคอลัมน์ชื่อ และไม่มีสิ่งใดเกี่ยวกับทุนที่ระบุตัวบุคคลนอกจากรหัสที่ท่านให้ไว้แล้วในแผ่นงาน Staff
- **หลักสูตรได้ประโยชน์ผ่านบุคลากรเท่านั้น** บุคลากรสายสอนของหลักสูตรมาจากแผ่นงาน Programme Teaching Staff ดังนั้นทุนของบุคคลที่ไม่ได้เชื่อมกับหลักสูตรใดในนั้นจะไม่ถึง Deep-Dive ใดเลย
- **อัปโหลดซ้ำเป็นการอัปเดต** โครงการจับคู่ด้วย Project Code และแถวทีมจับคู่ด้วยคู่ของรหัส การอัปโหลดไม่ลบอะไร หากต้องการลบให้ใช้ start over การ start over ของแผ่นงานใดก็ไม่แตะโครงการที่ connector เขียน
- **ทุนที่นำเข้าอยู่ร่วมกับ connector ของ KKU ได้** ฝ่ายใดก็ไม่แทนที่แถวของอีกฝ่าย การรีเฟรชรายวันของ connector ไม่แตะโครงการที่นำเข้า และการอัปโหลดไม่แตะโครงการของ connector

## Digital competency — cohorts และ modules

สองแผ่นงานป้อนข้อมูลให้ส่วน Digital competency ในหน้า Deep-Dive ของหลักสูตรและแดชบอร์ด Student DQ ให้โหลดทั้งสองแผ่น: คะแนนมาจากแผ่นงาน modules และจะไม่แสดงจนกว่าแผ่นงาน cohorts จะแสดงผู้มีคะแนนอย่างน้อยหกคน

**Digital Competency — Cohorts**: หนึ่งแถวต่อหนึ่งหลักสูตรต่อหนึ่งปีที่เข้าศึกษา ทุกคอลัมน์จำเป็น: **Programme Code**, **Entry Year**, **Students Tested** (อย่างน้อยห้า มิฉะนั้นไฟล์ถูกปฏิเสธ), **Students With Scores** (ห้ามเกิน Students Tested) และ **Students Passing All Modules** (ห้ามเกิน Students With Scores) อัตราผ่านที่แสดงคือจำนวนที่ผ่านหารด้วยจำนวนที่มีคะแนน

**Digital Competency — Modules**: หนึ่งแถวต่อหนึ่งหลักสูตรต่อหนึ่งปีที่เข้าศึกษาต่อหนึ่งโมดูล ทุกคอลัมน์จำเป็น: **Programme Code**, **Entry Year**, **Module** (1 ถึง 13), **Students Taking** (อย่างน้อยห้า), **Mean Score (0–100)** และ **Students In Scope** (ห้ามน้อยกว่า Students Taking) ค่าเฉลี่ยรวมคือค่าเฉลี่ยถ่วงน้ำหนักด้วยผู้สอบของโมดูล 1 ถึง 12 โมดูล 13 (ภาคปฏิบัติ) ถูกเก็บและวาดบนเรดาร์ แต่ไม่รวมในค่าเฉลี่ยนั้น แผ่น Guide แสดงชื่อโมดูล

- **13 โมดูลเป็นของกรอบการประเมินเอง** สถาบันที่ใช้แบบทดสอบอื่นต้องแมปเข้ากับแกนเหล่านี้ มิฉะนั้นเรดาร์จะมีข้อมูลน้อย
- **Entry Year เป็นปีคริสต์ศักราช** เก็บเป็นพุทธศักราช (บวก 543) เช่นเดียวกับแผ่นงาน cohort อื่น ปีพุทธศักราชจะถูกปฏิเสธ
- **ค่าเฉลี่ยนอกช่วง 0–100 จะถูกปฏิเสธ** พร้อมระบุมาตรา
- **เฉพาะหลักสูตรปริญญาตรี** Digital competency เป็นมาตรวัดระดับปริญญาตรี แถวของระดับอื่นถูกเก็บไว้ แต่ไม่มีคะแนนใดอ่านแถวนั้น
- **แต่ละแผ่นงานแทนที่สิ่งที่แผ่นงานนั้นอัปโหลดก่อนหน้า ต่อหลักสูตร** หลักสูตรที่ปรากฏในไฟล์จะถูกแทนที่แถวก่อนหน้าจากแผ่นงานเดียวกัน หลักสูตรที่ไฟล์ไม่ได้กล่าวถึงไม่ถูกแตะต้อง รวมถึงสิ่งที่แหล่งอื่นเขียนไว้ ให้อัปโหลด cohort ทั้งชุดของหลักสูตรในไฟล์เดียว
- ต่ำกว่าหกคนที่มีคะแนน หลักสูตรจะแสดงจำนวนและไม่แสดงคะแนน แทนที่จะแสดงตัวเลขที่อธิบายตัวบุคคล
- **แถวโมดูลที่มีผู้สอบต่ำกว่าห้าคนจะถูกปฏิเสธ** ให้รวมกลุ่มเล็ก (เช่น ข้ามปีที่เข้าศึกษา) หรือละแถวนั้น โมดูลนั้นจะไม่แสดงคะแนน
- **แผงความครอบคลุมของแดชบอร์ด DQ ว่างสำหรับข้อมูลที่นำเข้า** เพราะต้องใช้ข้อมูลส่งออกรายนักศึกษาที่ connector ของ DQ อ่านได้เท่านั้น จึงไม่อธิบายสิ่งที่ท่านอัปโหลด
- **นำเข้าโมดูล workshop ไม่ได้** รับเฉพาะโมดูลภาคทฤษฎี (1 ถึง 13) หมายเลขโมดูล workshop จะถูกปฏิเสธ

## Employer feedback

หนึ่งแผ่นงานป้อนข้อมูลให้รายการ **Top employers** ในส่วนผลลัพธ์ของบัณฑิตใน Deep-Dive หนึ่งแถวต่อหนึ่งหลักสูตรต่อหนึ่งปีที่สำรวจต่อหนึ่งนายจ้าง คอลัมน์: **Programme Code**, **Survey Year**, **Employer** (ไม่บังคับ), **Satisfaction (0–1)** และ **Respondents** ทุกคอลัมน์ยกเว้น Employer จำเป็น

- **เว้น Employer ว่าง** เพื่อให้ได้ตัวเลขเดียวที่ครอบคลุมนายจ้างทั้งหมด ระบบเก็บและแสดงเป็น "All employers" ใช้ชื่อองค์กรเท่านั้น ห้ามใช้ชื่อบุคคล
- **Satisfaction เป็นสัดส่วนระหว่าง 0 ถึง 1** เขียน 87 % เป็น 0.87 ค่าที่เกิน 1 จะถูกปฏิเสธ เพราะ 87 จะแสดงเป็น 8700 %
- **Respondents ต้องอย่างน้อยห้าคน** มิฉะนั้นไฟล์ถูกปฏิเสธ
- **Survey Year เป็นปีคริสต์ศักราช** ปีพุทธศักราชจะถูกปฏิเสธ
- **แทนที่ต่อหลักสูตร** หลักสูตรที่ปรากฏในไฟล์จะถูกแทนที่แถวก่อนหน้าจากแผ่นงานนี้ หลักสูตรที่ไฟล์ไม่ได้กล่าวถึงไม่ถูกแตะต้อง
- **ปรากฏที่ใด** ข้อมูลความพึงพอใจของนายจ้างแสดงในส่วน **Outcomes** ของ Deep-Dive ของหลักสูตร ซึ่งแสดงรายการนายจ้างอันดับต้น แม้หลักสูตรนั้นยังไม่มีการสำรวจผลลัพธ์ของบัณฑิต
- Employer ที่เว้นว่างกับที่พิมพ์ว่า "All employers" เป็นแถวเดียวกัน ไฟล์ที่ระบุทั้งสองแบบสำหรับหลักสูตรและปีเดียวกันจะถูกปฏิเสธว่าซ้ำ

## Population projections

หนึ่งแผ่นงานให้ขนาดของรุ่นประชากรที่อยู่เบื้องหลังมุมมองเพดานทางประชากรศาสตร์ (demographic ceiling) ตัววางแผนสถานการณ์ และตัวขับเคลื่อนสุขภาพด้านประชากร หากไม่มี ระบบจะใช้ชุดข้อมูล UN World Population Prospects (`un-wpp` ตัวเลขระดับประเทศของประเทศที่ connector ใช้) และในการติดตั้งของ KKU ใช้ชุดเริ่มต้นของ NESDC อัปโหลดแผ่นงานนี้เพื่อใช้ฉบับของสำนักงานสถิติแห่งชาติของท่าน หรือเพื่อให้ตัวเลข **ระดับภูมิภาค** คอลัมน์: **Region**, **Year**, **Age Group**, **Population** และ **Source Name** ทุกคอลัมน์จำเป็น

- **Region** เขียน `TH` สำหรับยอดรวมระดับประเทศ แถวระดับภูมิภาคจะขับเคลื่อนคะแนนสุขภาพด้านประชากรได้ก็ต่อเมื่อข้อความตรงกับภูมิภาคใน organisation profile ทุกตัวอักษร (เช่น "Northeast") ระบบไม่เคยใช้ตัวเลขระดับประเทศแทน ดังนั้นภูมิภาคที่ไม่ตรงจะทำให้ตัวขับเคลื่อนนั้นว่าง แทนที่จะให้คะแนนจากประชากรที่ไม่ถูกต้อง
- **Year** เป็นปีปฏิทินคริสต์ศักราช 2000 ถึง 2100 ปีพุทธศักราชจะถูกปฏิเสธ
- **Age Group** เป็น `15-17`, `18-22` หรือ `23-29` ค่าอื่นจะถูกปฏิเสธ ดังนั้นให้รวมอายุรายปีเข้าด้วยกันก่อน
- **Population** เป็นจำนวนคน ไม่ใช่หลักพัน และมากกว่าศูนย์
- **Source Name** เป็นข้อความอิสระ เช่น "NESDC 2023 edition" เก็บเป็น `xlsx:<name>` และแสดงทุกที่ที่อ้างอิงประมาณการนั้น ให้คงชื่อเดิมระหว่างการอัปโหลด: ไฟล์ผสานตาม region, year, age group และ source name ดังนั้นไฟล์ที่รีเฟรชจะอัปเดตฉบับเดิม และชื่อใหม่จะเพิ่มฉบับที่สอง
- **ฉบับใดชนะ** ตัวอ่านทุกตัวเลือกแผ่นงานที่อัปโหลดก่อน ตามด้วยชุดของ UN แล้วจึง NESDC และนับเฉพาะแหล่งที่มีแถวระดับประเทศของปีปัจจุบัน (และของภูมิภาค หากตัวอ่านต้องใช้) ให้ใส่ปีปัจจุบันด้วย มิฉะนั้นแผ่นงานจะถูกข้าม
- **Start over** ลบเฉพาะแถวที่แผ่นงานนี้เขียน

## Career skill demand

แผ่นงานนี้เป็นทางสำรองของ KMITL Skill Mapping API ซึ่งมหาวิทยาลัยที่นำระบบไปใช้มักเรียกใช้ไม่ได้ เพราะ KMITL ออกข้อมูลยืนยันตัวตนเมื่อมีการร้องขอโดยตรง ไม่ใช่แบบบริการตนเอง แผ่นงานนี้เขียนตารางเดียวกัน ดังนั้นคะแนน labour-market alignment คะแนน strategic-sector และการแมปหลักสูตรกับอาชีพจึงอ่านได้โดยไม่ต้องเปลี่ยน คอลัมน์: **Career Group**, **Career**, **Skill**, **Scope** (`Thailand` หรือ `Global`), **Data Source** (`Job postings` หรือ `Profiles`) และ **Share of Postings (%)** (จำเป็นทั้งหมด) และ **Career Sub-group** (ไม่บังคับ เก็บเป็น `General` เมื่อว่าง)

- **Share of Postings (%)** เป็นเปอร์เซ็นต์ 0 ถึง 100 (เขียน 12.5 สำหรับ 12.5 %) หน่วยเดียวกับที่ KMITL API ส่งกลับ ทักษะนับว่ามีอุปสงค์เมื่อตั้งแต่ 5 ขึ้นไป ค่าที่เกิน 100 จะถูกปฏิเสธ
- **Career Group** เฉพาะ `IT`, `Engineer`, `Health Science`, `Smart Farmer`, `New S Curve` และ `Food` ที่นับเป็นสาขายุทธศาสตร์ในคะแนน strategic-sector ชื่ออื่นอนุญาต และให้คะแนนเป็นไม่ใช่สาขายุทธศาสตร์
- **Skill** จับคู่โดยไม่สนตัวพิมพ์ กับชื่อภาษาอังกฤษก่อน แล้วชื่อภาษาไทยใน skill taxonomy ของท่าน ชื่อที่ไม่ตรงกับอะไรจะถูกเก็บโดยไม่มีลิงก์ ไม่มีคะแนน และจะนับไว้ในข้อความหลังอัปโหลด **อัปโหลดหลังจาก pipeline ของหลักสูตรสร้างทักษะของท่านแล้ว** และอัปโหลดอีกครั้งภายหลังเพื่อจับคู่ชื่อให้มากขึ้น
- อาชีพที่นำเข้าจะได้รหัสติดลบเพื่อไม่ให้ชนกับของ KMITL และคงรหัสนั้นเมื่ออัปโหลดซ้ำ การรัน connector ไม่แตะต้องรหัสเหล่านั้น
- ไฟล์ผสานตาม Career Group, Career Sub-group, Career, Skill, Scope และ Data Source **Start over** ลบเฉพาะแถวที่แผ่นงานนี้เขียน

## University rankings

หนึ่งแผ่นงานแสดงรายชื่อมหาวิทยาลัยที่การเลือกสถาบันเปรียบเทียบด้วย AI ใน Deep-Dive เลือกจากรายการนั้น เทมเพลตดาวน์โหลดมา **พร้อมรายการเริ่มต้นที่กรอกไว้แล้ว** (อันดับ QS และ THE ปี 2025 ของมหาวิทยาลัยประมาณ 60 แห่งทั่วโลก เอเชีย เอเชียตะวันออกเฉียงใต้ และไทย) ให้แก้ไขรายการนั้นแทนการเริ่มจากแผ่นเปล่า คอลัมน์: **University**, **Country**, **Region**, **Ranking Year** (จำเป็น), **QS World Rank**, **THE World Rank**, **QS Asia Rank**, **THE Asia Rank** และ **Website** (ไม่บังคับ)

- **University** ต้องเป็นชื่อภาษาอังกฤษ แถวของสถาบันท่านเองจะถูกตัดออกจากการเลือกสถาบันเปรียบเทียบ ก็ต่อเมื่อตรงกับชื่อภาษาอังกฤษใน organisation profile ทุกตัวอักษร มิฉะนั้นสถาบันอาจถูกเสนอเป็นสถาบันเปรียบเทียบของตนเอง
- **Region** เป็นหนึ่งใน `World`, `Asia`, `Southeast Asia` หรือ `Thailand` ซึ่งเป็นระดับที่ตัวเลือกใช้จัดมหาวิทยาลัยไว้ ค่าอื่นจะถูกปฏิเสธ
- **Ranking Year** เป็นปีคริสต์ศักราชของฉบับ ตัวเลือกอ่านเฉพาะปีล่าสุดในตาราง ดังนั้นในทางปฏิบัติรายการของปีใหม่จะแทนที่รายการเก่า
- **Ranks** เป็นจำนวนเต็ม 1 ขึ้นไป ค่าว่างหมายถึงไม่มีอันดับ ค่าอันดับที่ว่างเมื่ออัปโหลดซ้ำจะล้างอันดับที่เก็บไว้
- **ตัวเลขมาจากที่ใด** QS และ THE เผยแพร่ตารางต่อสาธารณะแต่ไม่มีฟีดข้อมูล ให้คัดลอกอันดับที่ต้องการ สำหรับอันดับวิจัยของไทย SCImago Institutions Rankings (scimagoir.com ตัวกรองประเทศ `?country=THA`) เป็นแหล่งฟรี
- การอัปโหลดผสานแถวตาม University และ Ranking Year **Start over** ลบเฉพาะแถวที่แผ่นงานนี้เขียน และจะปฏิเสธเมื่อมีหลักสูตรที่เลือกสถาบันเปรียบเทียบโดยอ้างอิงแถวเหล่านั้นอยู่

## Staff salary by funding

หนึ่งแผ่นงานป้อนข้อมูลให้การ์ด **Teaching-staff salary cost** ใน Deep-Dive ซึ่งแบ่งต้นทุนเงินเดือนของหลักสูตรตามผู้จ่าย หนึ่งแถวต่อหนึ่งคณะ ตำแหน่ง แหล่งเงิน และปีงบประมาณ คอลัมน์: **Faculty Code**, **Rank** (LECTURER, ASST_PROF, ASSOC_PROF หรือ PROF ตามแผ่นงาน Compensation), **Funding Source** (ข้อความอิสระ เช่น "Government budget" หรือ "University revenue"), **Fiscal Year**, **Headcount** และ **Mean**, **Min** และ **Max Monthly Salary (THB)**

- **เงินเดือนเป็นรายเดือน** ต่างจากแผ่นงาน Compensation ตัวเลขที่เกิน 500,000 จะถูกปฏิเสธเพราะน่าจะเป็นรายปี
- **Min ต้องไม่เกิน Mean และ Mean ต้องไม่เกิน Max**
- **Headcount ต้องอย่างน้อยห้า** ข้อความปฏิเสธระบุแถวและไม่อ้างอิงเงินเดือน
- **Fiscal Year เป็นปีคริสต์ศักราช** เก็บเป็นพุทธศักราช (2024 กลายเป็น 2567) ซึ่งเป็นวิธีที่มุมมองข้อมูลของผู้ดูแลระบบจะแสดง
- **Rank** เป็นหนึ่งใน LECTURER (อาจารย์), ASST_PROF (ผู้ช่วยศาสตราจารย์), ASSOC_PROF (รองศาสตราจารย์) หรือ PROF (ศาสตราจารย์)
- **Funding Source แสดงตามที่เขียน** จึงควรใช้การสะกดเดียวต่อหนึ่งแหล่ง ช่องว่างส่วนเกินจะถูกละเลยเมื่อเปรียบเทียบแถว
- การ์ดนี้ยังต้องใช้บุคลากร การมอบหมายหลักสูตร และข้อมูล Enrolment (จำนวนนักศึกษา) ของท่านด้วย โดยใช้ปีล่าสุดในแผ่นงานนี้และตำแหน่งของบุคลากรแต่ละคน
- **ผสาน**: แถวของปี คณะ ตำแหน่ง และแหล่งเงินเดียวกันจะถูกอัปเดต หาก connector ของงานบุคคลทำงานอยู่ด้วย connector จะไม่ลบแถวจากแผ่นงานนี้ แต่หากเขียนปี คณะ ตำแหน่ง และแหล่งเงินเดียวกัน ตัวเลขจากการรันครั้งถัดไปของ connector จะแทนที่ของท่าน

## ปี เงิน และอัตรา

สามข้อตกลง ซึ่งแต่ละข้อมีคำตอบผิดที่ดูเหมือนถูก

- **ทุกปีเป็นคริสต์ศักราช** เขียน 2025 ไม่ใช่ 2568 ปีพุทธศักราชเกินไป 543 ปี ซึ่งผ่านการทดสอบ "เป็นตัวเลขที่สมเหตุสมผลหรือไม่" ได้ ระบบจึงปฏิเสธไฟล์ทันที แทนที่จะเก็บไว้ภายใต้ปีที่ไม่มีใครถามหา
- **ปีของข้อมูลการเงินเป็นปีการศึกษา ไม่ใช่ปีงบประมาณ** ปีการศึกษาคาบเกี่ยวสองปีงบประมาณ ตัวเลขที่คัดลอกจากรายงานงบประมาณรายปีงบประมาณจึงอธิบายช่วงเวลาที่ต่างจากที่คอลัมน์ถาม
- **อัตราเป็นสัดส่วนระหว่าง 0 ถึง 1** เขียน 87 % เป็น `0.87` อัตรา `87` จะถูกปฏิเสธ หากไม่ตรวจ จะแสดงเป็นการมีงานทำ 8700 %

เงินเดือนเป็น **รายเดือน** หน่วยบาท ในแผ่นงาน Graduate Outcomes และเป็น **รายปี** ในแผ่นงาน Compensation แต่ละแผ่นระบุไว้ในคอลัมน์ guide ของตนเอง ใส่เครื่องหมายจุลภาคได้

คอลัมน์ปีบางคอลัมน์ถูกเก็บโดยแปลงเป็นพุทธศักราช เพราะเป็นวิธีบันทึกข้อมูลของงานทะเบียนที่อยู่ข้างกัน ได้แก่ **Student Cohorts**, **Alumni Cohorts**, **Admission Campaigns** และ **Class Offerings** ท่านเขียนเป็นปีคริสต์ศักราชเสมอ มุมมองข้อมูลของผู้ดูแลระบบจะแสดงปีบวก 543

## ข้อมูลส่วนบุคคล

มีเพียงแผ่นงานเดียวที่เกี่ยวกับบุคคล คือ **Staff** แผ่นงานนี้ขอชื่อ รหัสพนักงานของท่านเอง และตำแหน่ง

แผ่นงานนี้ตั้งใจ **ไม่** ขอวันเดือนปีเกิด มุมมองความเสี่ยงด้านการสืบทอดตำแหน่ง (succession-risk) อ่านวันเกษียณ ซึ่งตอบคำถามเดียวกันและเปิดเผยน้อยกว่ามาก จึงเป็นคอลัมน์ที่ให้ใช้แทน ไม่มีคอลัมน์เลขบัตรประจำตัวประชาชนในแผ่นงานใดในรูปแบบใด หากระบบของท่านจับคู่บุคคลด้วยเลขดังกล่าว ให้ใช้ต่อไปในฝั่งของท่าน แล้วให้รหัสพนักงานของท่านแก่เรา ซึ่งโดยลำพังไม่ใช่ข้อมูลอ่อนไหว

**Compensation ปฏิเสธแถวที่ครอบคลุมน้อยกว่าห้าคน** ที่ขนาดนั้น ค่าเฉลี่ยใกล้เคียงกับเงินเดือนรายบุคคลพอที่จะระบุตัวบุคคลได้ ข้อความระบุแถวและไม่แสดงตัวเลขซ้ำ

หากเซลล์ใดในแผ่นงานใดดูเหมือนเลขบัตรประจำตัวประชาชน ไฟล์จะถูกปฏิเสธ และข้อความจะบอกแถวและคอลัมน์ โดยไม่แสดงค่านั้น

## ก่อนเริ่ม: ผู้ดูแลระบบคนแรก

ทุกอย่างในหน้านี้อยู่หลัง `/admin` และระบบที่ติดตั้งใหม่ยังไม่มีผู้ดูแลระบบเลย การ seed เป็นความสะดวกของมหาวิทยาลัยขอนแก่นที่สถาบันอื่นไม่ได้รัน และ single sign-on ให้ทุกบัญชีมีบทบาทต่ำสุด ทั้งสองทางจึงไม่สร้างผู้ดูแลระบบ

ให้เปิดระบบในเบราว์เซอร์แทน การติดตั้งใหม่จะพาท่านไปที่ **`/setup`** ซึ่งขอชื่อ ที่อยู่อีเมล และรหัสผ่าน แล้วสร้างผู้ดูแลระบบคนแรกจากข้อมูลเหล่านั้น บัญชีนั้นสร้างบัญชีอื่นทั้งหมดได้ แล้วงานในหน้านี้จึงเริ่มได้

ข้อควรรู้สองข้อ

- **หน้านี้เปิดให้ทุกคนที่เข้าถึงที่อยู่ได้ และคนแรกที่ใช้จะเป็นผู้ดูแลระบบ** ไม่ต้องมีรหัสผ่าน ขอเพียงเป็นคนแรก ให้ยึดครองการติดตั้งทันทีที่ระบบทำงาน แทนที่จะปล่อยไว้ข้ามสุดสัปดาห์ระหว่างที่จัดการเอกสารอื่น
- **หน้านี้ปิดถาวรทันทีที่ใช้งาน** และคงปิดอยู่แม้ผู้ดูแลระบบคนนั้นถูกลบในภายหลัง หลังจากนั้น `/setup` จะพาท่านไปหน้าลงชื่อเข้าใช้เท่านั้น

ลงชื่อเข้าใช้ด้วยอีเมลและรหัสผ่านนั้น แบบฟอร์มรหัสผ่านจะถูกซ่อนเมื่อตั้งค่า single sign-on แล้ว หากยังต้องใช้หลังจากนั้น ให้ไปที่ `/signin?password=1` ให้เลื่อนบัญชี single sign-on หนึ่งบัญชีเป็นผู้ดูแลระบบก่อนพึ่งพาวิธีนี้ เพื่อไม่ให้การติดตั้งอาศัยรหัสผ่านเพียงตัวเดียว

## ไปที่ใด

`/admin/data-setup` แสดงทุกชุดข้อมูลภายใต้ **Institution data** จัดกลุ่มตามลำดับที่ควรโหลด พร้อมจำนวนแถวของแต่ละชุดและเวลาที่อัปโหลดล่าสุด เปิดหนึ่งชุด แล้วท่านจะได้หน้าที่มีแผงนำเข้าอยู่ด้านบน และข้อมูลที่เก็บอยู่ในปัจจุบันอยู่ด้านล่าง

ท่านต้องมีบัญชีผู้ดูแลระบบ การล้างชุดข้อมูลต้องใช้สิทธิ์ `imports:destroy` ซึ่งผู้ดูแลระบบมีโดยค่าเริ่มต้น

## ทำงานอย่างไร

1. **ดาวน์โหลดเทมเพลต** เทมเพลตถูกสร้างสำหรับการติดตั้งของท่าน คอลัมน์จึงตรงกับที่ระบบจะรับเสมอ เทมเพลต enrolment, finance และ graduate-outcome มาแบบ **ว่าง** (มีเฉพาะหัวคอลัมน์): เพิ่มหนึ่งแถวต่อหลักสูตรและปีที่ท่านมีตัวเลข และละปีที่ไม่มี แถว enrolment ต้องมีตัวเลขอย่างน้อยหนึ่งค่า แถวที่มีเพียงรหัสหลักสูตรกับปีจะถูกปฏิเสธ เพราะการเก็บจะบันทึกค่าศูนย์ที่ไม่มีใครนับ

   เทมเพลต student-cohort และ alumni-cohort มาแบบ **กรอกไว้ล่วงหน้า** โดยมีหนึ่งแถวต่อหลักสูตรที่เปิดสอนต่อปี ค่าว่าง เพื่อให้ท่านกรอกตัวเลขแทนการพิมพ์รหัสหลักสูตรซ้ำ อัปโหลดไฟล์ตามที่ได้มา: **แถวที่กรอกไว้ล่วงหน้าแล้วท่านเว้นว่างจะถูกข้าม** จึงไม่ต้องลบแถวที่เหลือ ไฟล์ที่ทุกแถวว่างจะถูกปฏิเสธ แทนที่จะรายงานว่าอัปโหลดสำเร็จโดยไม่มีอะไรเลย
2. **กรอกแผ่นข้อมูล** ทุกสมุดงานมีสองแผ่น คือข้อมูล และแผ่น **Guide** ที่อธิบายแต่ละคอลัมน์ พร้อมตัวอย่างและค่าที่อนุญาต แผ่น Guide จะถูกละเลยตอนอัปโหลด ท่านเขียนในแผ่นนั้นได้อย่างอิสระ
3. **อัปโหลด** ไฟล์จะถูกตรวจในระหว่างที่ท่านรอ หากมีสิ่งใดผิด ท่านจะได้รายการแถวและคอลัมน์ที่ต้องแก้ และ **ไม่มีอะไรถูกเก็บ**

โหลดตามลำดับ: Faculties แล้ว Departments แล้ว Programmes แล้ว metric ต่าง ๆ แต่ละชุดอ้างอิงชุดก่อนหน้าด้วยรหัส

## อัปโหลดอีกครั้งในภายหลัง

อัปโหลดชุดข้อมูลเดิมได้บ่อยเท่าที่ต้องการ แถวจับคู่ด้วยรหัส

- รหัสที่มีอยู่ในระบบแล้วจะถูก **อัปเดต**
- รหัสที่ใหม่จะถูก **เพิ่ม**
- สิ่งใดที่ไฟล์ของท่านไม่ได้กล่าวถึงจะ **ไม่ถูกแตะต้อง**

ไฟล์ที่ครอบคลุมเพียงสามหลักสูตรที่เปลี่ยนในภาคการศึกษานี้ จึงทำเฉพาะสิ่งนั้น และไม่แตะอย่างอื่น

เช่นเดียวกันกับ **คอลัมน์** ในชุดข้อมูล metric: เซลล์ว่างจะคงค่าที่เก็บไว้ แทนที่จะตั้งเป็นศูนย์ หากท่านมีจำนวนผู้สมัครแต่ไม่มีจำนวนผู้สำเร็จการศึกษา ให้เว้นคอลัมน์ผู้สำเร็จการศึกษาว่าง และคอลัมน์เหล่านั้นจะคงค่าที่แหล่งอื่นให้ไว้

การอัปโหลดไฟล์ที่เหมือนกันทุกไบต์ซ้ำจะไม่ทำอะไร และระบบจะแจ้งเช่นนั้น

## กฎที่การอัปโหลดบังคับใช้

**ต้องมีคอลัมน์ที่จำเป็น และคอลัมน์ที่ไม่รู้จักจะถูกปฏิเสธ** ท่านละคอลัมน์ที่ไม่บังคับได้ ละคอลัมน์ที่จำเป็นไม่ได้ และเพิ่มคอลัมน์ที่ชุดข้อมูลไม่ได้อธิบายไว้ไม่ได้ ที่เป็นเช่นนี้โดยเจตนา มิฉะนั้นคอลัมน์ข้อมูลส่วนบุคคลที่หลงเข้ามาจะถูกรับไว้เงียบ ๆ

**ทุกรหัสต้องมีอยู่แล้ว** แถวที่ระบุรหัสหลักสูตร คณะ ภาควิชา หรือพนักงานที่ไม่อยู่ในการอัปโหลดก่อนหน้า จะทำให้ทั้งไฟล์ถูกปฏิเสธ และข้อความจะแสดงรายการแต่ละแถว: "... is not a known programmes code. Upload that dataset first, or correct the value." ให้เพิ่มแถวที่ขาดในแผ่นงานก่อนหน้า หรือลบแถวที่อ้างถึง ข้อมูลส่งออกเก่ามักระบุหลักสูตรที่ปิดไปแล้ว จึงควรคาดว่าจะพบเรื่องนี้หนึ่งครั้ง

**การอัปโหลดหนึ่งครั้งรับได้สูงสุด 5000 แถว** ไฟล์ที่ใหญ่กว่านี้จะถูกปฏิเสธด้วยข้อความ "This file has 8002 rows; the limit is 5000. Split it into smaller files." ให้แบ่งไฟล์ใหญ่ (ส่วนมากคือ publications) เป็นหลายส่วนแล้วอัปโหลดทีละส่วน

**ห้ามมีตัวระบุส่วนบุคคล** เซลล์ที่มีเลขบัตรประจำตัวประชาชนทำให้ไฟล์ล้มเหลว ข้อความระบุแถวและคอลัมน์ และไม่แสดงค่านั้นซ้ำ

**กลุ่มเล็กจะถูกปฏิเสธ** ในชุดข้อมูลที่มีจำนวนคน เพื่อไม่ให้คำนวณตัวเลขของบุคคลใดจากค่าเฉลี่ยได้

**ไฟล์ที่เล็กกว่ามากจะถูกสอบถาม ในกรณีที่อาจทำให้แถวหายไป** ชุดข้อมูลที่แทนที่ภาคการศึกษาหรือรายการของหลักสูตร (class offerings, programme course lists) จะปฏิเสธไฟล์ที่มีแถวน้อยกว่าครึ่งหนึ่งของที่เก็บอยู่สำหรับภาคการศึกษาหรือหลักสูตรนั้น โดยถือว่าน่าจะเป็นข้อมูลส่งออกที่ไม่ครบ พร้อมปุ่มให้อัปโหลดต่อไปหากท่านแน่ใจว่าถูกต้อง ชุดข้อมูลอื่นทุกชุดเพียงเพิ่มหรืออัปเดตแถว ไฟล์ที่สั้นจึงไม่มีวันทำให้อะไรหายและถูกรับไว้ ท่านแบ่งไฟล์ใหญ่เป็นหลายส่วนได้โดยไม่ต้องยืนยันส่วนสุดท้ายที่เล็ก

## สิ่งที่ควรรู้เกี่ยวกับสเปรดชีต

- **มุมมองสรุปรวม (roll-up) รีเฟรชเอง** หลังอัปโหลด programmes, enrolment, finance หรือ outcomes ในการติดตั้งที่อัปเกรดมาจากก่อนการเปลี่ยนแปลงนี้ ให้รัน `pnpm outcomes:refresh-derived` หนึ่งครั้ง
- **รหัสที่ขึ้นต้นด้วยศูนย์** ให้ตั้งรูปแบบเซลล์เป็นข้อความก่อน มิฉะนั้น Excel จะเปลี่ยน `007` เป็น `7` ก่อนที่ระบบจะเห็น
- **แถวว่างจะถูกละเลย** แถวว่างท้ายไฟล์จึงไม่เป็นไร
- **วันที่** ควรเขียนเป็น `YYYY-MM-DD` หรือเป็นเซลล์วันที่จริง
- **จุลภาคใช้คั่นหลักพัน ไม่ใช่จุดทศนิยม** `1,250,000` ใช้ได้ `1234,56` จะถูกปฏิเสธ แทนที่จะอ่านเป็น 123456 หากภาษาในเครื่องของท่านใช้จุลภาคเป็นทศนิยม ให้เขียน `1234.56`
- **หมายเลขแถวในข้อความข้อผิดพลาดคือหมายเลขแถวที่ท่านเห็นใน Excel** ท่านจึงไปที่บรรทัดนั้นได้ทันที

## Start over

ทุกชุดข้อมูลมีปุ่มควบคุม **Start over** ที่ท้ายหน้า ปุ่มนี้ลบแถวที่นำเข้า และไม่แตะสิ่งที่มาจาก connector หรือการตั้งค่าเดิม ท่านต้องพิมพ์ชื่อชุดข้อมูลเพื่อยืนยัน

ควรเข้าใจข้อควรระวังต่อไปนี้ก่อนใช้

- **ไฟล์ที่อัปโหลดถูกเก็บไว้** ทำ start over แล้วอัปโหลดอีกครั้ง ท่านก็กลับสู่สภาพเดิม นี่เป็นทางเดียวที่จะกลับ ดังนั้นอย่าลบสมุดงานจากเครื่องของท่านเองด้วย
- **ปฏิเสธเมื่อมีข้อมูลอื่นพึ่งพาอยู่** ท่านล้าง Faculties ไม่ได้ขณะที่ยังมี Departments หรือ Programmes และล้าง Programmes ไม่ได้ขณะที่ยังมีตัวเลข enrolment, finance หรือ outcome เพราะการล้างจะพาทุกอย่างที่ผูกอยู่ไปด้วย รวมถึงแถวที่ connector เขียนและไม่มีการอัปโหลดใดเคยแตะ ข้อความจะระบุสิ่งที่จะถูกทำลาย ให้ล้างจากล่างขึ้นบน
- **แถวที่ connector สร้างจะคงอยู่** แม้การอัปโหลดของท่านจะแก้ไขแถวนั้น แถวนั้นยังเป็นของ connector
- **แถวที่ไม่มีบันทึกต้นทางจะถูกรับเป็นของการอัปโหลดที่แก้ไขมัน** และ start over จะลบแถวนั้น นี่เป็นทางเดียวที่แถวเช่นนั้นจะมองเห็นได้เลย เพราะแอปซ่อนข้อมูลที่ตรวจสอบต้นทางไม่ได้ การอัปโหลดที่แตะแถวนั้นจึงรับความเป็นเจ้าของ หากท่านกำลังแก้ตัวเลขที่โหลดไว้ก่อนที่ระบบนี้จะบันทึกที่มาของข้อมูล start over จะลบทั้งแถว ไม่ใช่เฉพาะส่วนที่ท่านแก้

## หากการอัปโหลดไม่ปรากฏ {#if-an-upload-does-not-appear}

แถวที่นำเข้ามีบันทึกว่าการอัปโหลดใดสร้างแถวนั้น และแอปซ่อนข้อมูลที่ตรวจสอบต้นทางไม่ได้ หากอัปโหลดสำเร็จแต่ไม่มีอะไรแสดง สาเหตุที่พบบ่อยคือขาดแถวของแหล่งข้อมูล (data source) ให้รัน `pnpm data-sources:sync --apply` ซึ่งสร้างหนึ่งแถวต่อชุดข้อมูลโดยไม่แตะสิ่งอื่น แล้วอัปโหลดอีกครั้ง (`pnpm setup` และทุกการ deploy ขึ้นระบบจริงรันคำสั่งนี้อยู่แล้ว จึงมักเกิดกับฐานข้อมูลที่เก่ากว่าชุดข้อมูลใหม่)
