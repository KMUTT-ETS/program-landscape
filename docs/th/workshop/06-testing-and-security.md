# Session 6: การทดสอบ การตรวจสอบความถูกต้อง และความปลอดภัย

> **English:** [`06-testing-and-security.md`](../../workshop/06-testing-and-security.md)

**เวลา** ประมาณ 90 นาที

**ผลลัพธ์** ท่านรันการทดสอบที่ปกป้องการคำนวณ ดูว่าใครมีสิทธิ์เห็นอะไร และดูการทำงานของระบบที่กันข้อมูลส่วนบุคคลออก
ทุกแบบฝึกหัดใช้มหาวิทยาลัยตัวอย่างจาก session 3

## รันการทดสอบ

ชุดทดสอบทั้งหมดรันด้วย `pnpm test` ใช้เวลาหลายนาที และบางการทดสอบอ่านฐานข้อมูลบนเครื่อง
จึงให้เริ่มจากการทดสอบของ Program Health Score ซึ่งเป็นคะแนนเบื้องหลังส่วนใหญ่ของ Deep-Dive
การทดสอบเหล่านี้ไม่ต้องใช้อะไรเพิ่ม:

```bash
pnpm --filter @kku/db exec vitest run test/health-score.test.ts
```

เปิด `packages/db/test/health-score.test.ts` แล้วหาการทดสอบเรื่องข้อมูลที่ขาดหาย กฎที่ตรวจคือ
ตัวเลขที่ขาดหายจะไม่ถูกนำมาเฉลี่ย ไม่นับเป็น 0 หรือ 50 และคะแนนจะรายงานว่าข้อมูลครบเพียงใด
ลองถาม assistant ของท่าน:

```text
In packages/db/test/health-score.test.ts, find the tests that check what happens
when a programme has no data for a driver. Explain the rule in two sentences and
point to the code in packages/db/src/health-score.ts that applies it.
```

วิธีการเบื้องหลังแต่ละคะแนนอธิบายไว้ใน
[ระเบียบวิธีของ health score](../../methodologies/health-score.md)

## ใครเห็นอะไรได้

ผู้ใช้ที่ลงชื่อเข้าใช้แต่ละคนมีหนึ่งบทบาท:

| บทบาท | เห็น |
|---|---|
| Super admin | ทุกอย่าง รวมถึงการดูแลระบบและคิวงาน |
| System admin | ทุกอย่าง ยกเว้นการจัดการคิวงาน |
| University user | ทุกหลักสูตร อ่านอย่างเดียว |
| Faculty user | หลักสูตรของหนึ่งคณะ |
| Program user | หนึ่งหลักสูตร |

ทุกคำขอไปยัง Deep-Dive ผ่านการตรวจสองชั้น `@Authorized` ตรวจว่าบทบาทมีสิทธิ์นั้น
และ `assertProgramAccessible` ตรวจว่าหลักสูตรอยู่ในขอบเขตของผู้ใช้ ชื่อบุคลากรมีกฎเพิ่มอีกหนึ่งข้อ:
เฉพาะผู้ดูแลระบบ Faculty user ของคณะที่หลักสูตรสังกัด และ Program user ของหลักสูตรนั้นจึงจะเห็นชื่อ
University user เปิดได้ทุกหลักสูตรแต่ไม่เห็นชื่อเลย ผู้อื่นจะเห็นส่วนเดียวกัน
แต่ไม่มีชื่อ รหัสพนักงาน และความเชี่ยวชาญ รายละเอียดอยู่ใน [บทบาทและสิทธิ์](../../auth/rbac.md)

### ลองทำ

ในฐานะ super administrator ท่านดูระบบในบทบาทอื่นได้โดยไม่ต้องออกจากระบบ

1. เปิดเมนูผู้ใช้ที่มุมขวาบน แล้วเลือก "Switch role"
2. เลือก "University user" เปิด Deep-Dive ของ `WDU-CPE-BE` แล้วเลื่อนไปที่ "Faculty capability"
   รายชื่อบุคลากรจะแสดงโดยไม่มีชื่อหรือรหัส
3. Switch role อีกครั้ง เลือก "Program user" แล้วกำหนดขอบเขตเป็น `WDU-ME-BE`
   เปิด Deep-Dive ของ `WDU-CPE-BE` อีกครั้ง หน้าจะไม่เปิด และอธิบายว่าผู้ใช้นี้ไม่มีสิทธิ์
   เพราะหลักสูตรอยู่นอกขอบเขต
4. เปิด Deep-Dive ของ `WDU-ME-BE` หน้าจะเปิดพร้อมชื่อ เพราะเป็นหลักสูตรของผู้ใช้นี้เอง
5. คลิก "Stop impersonating" ที่แถบด้านบนของหน้า

## กันข้อมูลส่วนบุคคลออก

ระบบทำงานกับข้อมูลระดับกลุ่ม ข้อมูลส่วนบุคคลถูกกันไว้หลายจุด:

- **การอัปโหลดรับเฉพาะคอลัมน์ของแม่แบบ** คอลัมน์เกินถูกปฏิเสธ คอลัมน์ที่ไม่มีใครอธิบายไว้จึงเล็ดลอดเข้ามาไม่ได้
- **การอัปโหลดปฏิเสธค่าที่คล้ายเลขประจำตัวประชาชน** ในทุกคอลัมน์ และข้อความแจ้งจะไม่แสดงค่านั้นซ้ำ
- **กลุ่มเล็กถูกปฏิเสธ** จำนวนคนต่ำกว่า 5 เช่นแบบสำรวจบัณฑิตที่มีผู้ตอบ 3 คน ทำให้ทั้งแฟ้มไม่ผ่าน
  เพราะกลุ่มที่เล็กขนาดนั้นระบุตัวบุคคลได้
- **คำตอบจาก AI ถูกกรอง** `sanitizeAiOutput` แทนที่เลขประจำตัวประชาชน หมายเลขโทรศัพท์
  และอีเมลส่วนตัวในผลลัพธ์ของ model ด้วยเครื่องหมาย `[REDACTED: ...]` ที่มองเห็นได้
- **log ถูกปกปิด** log ของคำขอตัด header การยืนยันตัวตน cookie และเหตุผลการส่งออกข้อมูลออก
- **ทุกการแก้ไขถูกบันทึก** ทุกการอัปโหลดและการเปลี่ยนการตั้งค่าเขียนแถว audit ผ่าน `@AuditLog`

การจัดการข้อมูลส่วนบุคคลตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล อยู่ใน [PDPA](../../pdpa.md)

### ลองทำ

1. สร้างตัวเลขทดสอบที่มีรูปแบบเหมือนเลขประจำตัวประชาชน คำสั่งนี้สุ่มตัวเลขบนแล็ปท็อปของท่าน
   และไม่ใช่ของบุคคลใด

```bash
node -e "const d=Array.from({length:12},(_,i)=>i?Math.floor(Math.random()*10):1+Math.floor(Math.random()*8));const s=d.reduce((t,x,i)=>t+x*(13-i),0);console.log(d.join('')+(11-s%11)%10)"
```

2. คัดลอก `workshop/sample-data/07-faculty-members.xlsx` เปิดสำเนา แล้ววางตัวเลขลงในช่อง
   "Specialization" ของแถวใดก็ได้
3. อัปโหลดสำเนาที่หน้าชุดข้อมูล Staff แฟ้มจะถูกปฏิเสธด้วยข้อความ "This cell looks like a personal
   identifier (national ID)." ข้อความระบุแถวและคอลัมน์ แต่ไม่แสดงตัวเลข
4. ในสำเนาใหม่ เพิ่มคอลัมน์หัวข้อ "Citizen ID" ใส่ข้อความใดก็ได้ แล้วอัปโหลด
   แฟ้มจะถูกปฏิเสธด้วยข้อความ "Unexpected column(s): Citizen ID."

เมื่อแฟ้มถูกปฏิเสธ ระบบจะไม่จัดเก็บอะไรเลย

## เสร็จเมื่อ

- การทดสอบ health score ผ่านบนแล็ปท็อปของท่าน
- ท่านเห็นชื่อบุคลากรถูกซ่อนสำหรับ University user และ Deep-Dive ไม่เปิดสำหรับ Program user ของหลักสูตรอื่น
- การอัปโหลดทั้งสองแบบถูกปฏิเสธด้วยข้อความข้างต้น
