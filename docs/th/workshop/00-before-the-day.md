# ก่อนวันอบรม

> **English:** [`00-before-the-day.md`](../../workshop/00-before-the-day.md)

ทำส่วนนี้ที่บ้าน เริ่มหลังได้รับ[แจ้งล่วงหน้า](./early-notice.md) และทำให้เสร็จภายใน
**กำหนดส่งแบบฟอร์มความพร้อม 19 พฤศจิกายน เวลา 18:00 น.** การประชุมเตรียมความพร้อมออนไลน์วันที่
16 พฤศจิกายนจะพาทำตามหน้านี้ ต้องดาวน์โหลดหลาย GB และเครือข่ายในห้องอบรมอาจช้า
ใช้เวลาหนึ่งถึงสองชั่วโมง ส่วนใหญ่เป็นการรอ
นำแล็ปท็อปที่ตั้งค่าระบบไว้แล้วและยืนยันผู้ดูแลระบบแล้วมาในวันอบรม

**ผลลัพธ์** ท่านมาถึงพร้อมแล็ปท็อปที่รันแอปได้ AI key ที่ใช้งานได้ และ AI coding assistant วันอบรมจึงเริ่มที่งานจริง ไม่ใช่การติดตั้ง

## แล็ปท็อปของท่าน

- หน่วยความจำอย่างน้อย 16 GB และดิสก์ว่างอย่างน้อย 25 GB
- Windows 10 หรือ 11, macOS หรือ Linux บน Windows ให้ทำงานภายใน WSL2
- มีสิทธิ์ติดตั้งซอฟต์แวร์ แล็ปท็อปที่มหาวิทยาลัยดูแลบางเครื่องบล็อก WSL2 หรือ Docker
  ให้สอบถามฝ่าย IT ของท่านแต่เนิ่น ๆ

## ติดตั้งเครื่องมือ

- **Windows:** ทำตาม [การติดตั้งบน Windows ด้วย WSL2](../guides/windows-wsl2.md)
  ซึ่งติดตั้ง WSL2, Docker, Git และ Node.js
- **macOS หรือ Linux:** ติดตั้ง Git, Docker พร้อม Compose v2 และ Node.js 24 (24.22.1 ขึ้นไป) ตามรายการใน
  [Getting started ขั้นที่ 1](../tutorials/getting-started.md#1-ตรวจสอบสิ่งที่ต้องมี)

## ดาวน์โหลดโค้ดและรัน setup หนึ่งครั้ง

ทำตาม [Getting started](../tutorials/getting-started.md) ขั้นที่ 2, 3 และ 4:
clone repository สร้าง `.env` และรันการตั้งค่าครั้งเดียว
การตั้งค่าจะดาวน์โหลดแพ็กเกจทั้งหมดและสร้าง Docker image ทุกตัว ซึ่งเป็นส่วนที่ไม่ควรทำบนเครือข่ายของห้องอบรม

## ขอ AI key และตรวจสอบว่าใช้งานได้

ท่านต้องมี key สำหรับ pipeline ใน session 3 วิธีขอ key อยู่ใน
[Getting started ขั้นที่ 1](../tutorials/getting-started.md#1-ตรวจสอบสิ่งที่ต้องมี)
Google Gemini key เป็นทางเลือกที่ง่ายที่สุด เพราะใช้ทำ embedding ได้ด้วย หากมีเพียง OpenRouter key
ให้ตั้ง `AI_OPENROUTER_EMBEDDING_MODEL` ตามที่หน้านั้นอธิบาย

ตรวจสอบ key แต่ละตัวด้วยคำขอเดียว ใส่ key ของท่านแทนส่วนที่อยู่ในวงเล็บมุม
ขึ้นต้นบรรทัดด้วยช่องว่าง เพื่อให้ shell ส่วนใหญ่ไม่บันทึกคำสั่งนี้ไว้ในประวัติ

```bash
 curl -s "https://generativelanguage.googleapis.com/v1beta/models?key=<your-gemini-key>" | head -c 300
```

ท่านควรเห็นส่วนต้นของรายการ model หากคำตอบมี `API_KEY_INVALID` แปลว่า key ไม่ถูกต้อง

หากใช้ OpenRouter ด้วย:

```bash
 curl -s https://openrouter.ai/api/v1/key -H "Authorization: Bearer <your-openrouter-key>"
```

ท่านควรเห็นวงเงินและยอดใช้ของ key ตรวจสอบว่ายังมีเครดิตเหลือ

## ติดตั้ง AI coding assistant

Session 2, 4 และ 5 ใช้ AI coding assistant ที่อ่าน repository ได้ ใช้เครื่องมือที่ท่านใช้อยู่แล้ว
เช่น Claude Code, GitHub Copilot, Cursor หรืออื่น ๆ prompt ในหน้าเหล่านี้เป็นข้อความธรรมดาที่ใช้ได้กับทุกเครื่องมือ

หากยังไม่มี ให้ติดตั้ง **opencode** ซึ่งใช้ได้ฟรี บน Windows ให้ติดตั้งภายใน Ubuntu (WSL2)

```bash
curl -fsSL https://opencode.ai/install | bash
opencode auth login
```

ลงชื่อเข้าใช้เมื่อระบบถาม จากนั้นเริ่ม `opencode` ในโฟลเดอร์โครงการ พิมพ์ `/models`
แล้วเลือก model ที่ชื่อลงท้ายด้วย `free` รายการ model ฟรีเปลี่ยนบ่อย ให้เลือกจากรายการที่เห็นในวันนั้น
ไม่ใช่ชื่อจากหน้านี้ ท่านจะเชื่อม Gemini key หรือ OpenRouter key กับ opencode แทนก็ได้

## เริ่มระบบหนึ่งครั้ง

เริ่มระบบด้วย `pnpm dev` ตรวจว่าระบบทำงานปกติ แล้วยืนยันผู้ดูแลระบบที่ `/setup`
ตาม [Getting started](../tutorials/getting-started.md) ขั้นตอนที่ 5, 6 และ 7
ผู้ที่เปิดหน้า setup คนแรกจะเป็นผู้ดูแลระบบ จึงควรทำทันที

จากนั้นเปิด `/admin/data-sources` คลิก `un-wpp` แล้วคลิก "Run now" connector นี้ไม่ต้องใช้ key
และดาวน์โหลดประมาณการประชากรของ UN ประมาณ 68 MB ท่านจึงไม่ต้องดาวน์โหลดอีกในห้องอบรม

- **เก็บฐานข้อมูลนี้ไว้** ในวันที่ 1 ให้เข้าระบบด้วยผู้ดูแลระบบที่สร้างไว้ตอนนี้ ไม่ต้องยืนยันใหม่
- ท่านจะนำเข้าข้อมูลของท่านเองและรัน pipeline ในวันที่ 1 ใน Session 3
  AI key ของท่านได้รับการตรวจแล้วด้วยคำขอด้านบน

## เตรียมข้อมูลของหลักสูตร

เลือกเส้นทางข้อมูล (A ข้อมูลจริง B ผสม C จำลอง) ตามที่อธิบายใน
[แจ้งล่วงหน้า](./early-notice.md#เลือกเส้นทางข้อมูล)

สำหรับแฟ้มที่ขอจากมหาวิทยาลัยได้ (เส้นทาง A และ B):

1. ส่งออกชุดข้อมูลตามรายการใน
   [Get Program Deep-Dive working ขั้นตอนที่ 2](../tutorials/program-deep-dive.md#ขั้นตอนที่-2-อัปโหลดโครงสร้างองค์กรและหลักสูตร)
   อย่างน้อยคือ คณะ ภาควิชา หลักสูตร บุคลากร อาจารย์ประจำหลักสูตร การรับเข้า การเงิน และผลลัพธ์บัณฑิต
2. กรอกลงในแม่แบบ ผู้ดำเนินการจะส่งแม่แบบเปล่าครบทั้ง 26 แฟ้มเป็นชุดเดียว เรียงหมายเลขตามลำดับการอัปโหลด
   ท่านสร้างชุดนี้เองได้ด้วย `pnpm workshop:templates --out <folder>` หรือดาวน์โหลดทีละแม่แบบจากหน้าของ
   แต่ละชุดข้อมูลใน `/admin/data-setup` แผ่นงาน "Guide" ในแต่ละแม่แบบอธิบายทุกคอลัมน์ ส่วนรายละเอียดทั้งหมดอยู่ใน
   [การนำเข้าข้อมูลจาก spreadsheet](../data-import.md)
3. **ลบข้อมูลส่วนบุคคลออกก่อนที่แฟ้มจะออกจากสำนักงานของท่าน** ไม่มีเลขประจำตัวประชาชน
   ไม่มีวันเกิด ไม่มีที่อยู่หรือหมายเลขโทรศัพท์ ระบบนำเข้าจะปฏิเสธแฟ้มที่มีค่าคล้ายเลขประจำตัวประชาชน
   แต่อย่าพึ่งพาการตรวจนี้
4. นำแฟ้ม PDF หลักสูตรของอย่างน้อยหนึ่งหลักสูตรมาด้วย (จำเป็น) หากไม่มี Program Deep-Dive จะทำงานได้ไม่ครบ
5. ทราบชื่อภาษาไทยของมหาวิทยาลัยตามที่เขียนในตารางรับสมัคร TCAS ทุกตัวอักษร

สำหรับชุดข้อมูลที่ขอไม่ได้ (เส้นทาง B) หรือทุกชุด (เส้นทาง C) ให้สร้างด้วย `pnpm workshop:mock`
ตามที่อธิบายใน
[Session 3](./03-university-data.md#ไม่มีแฟ้มส่งออก-สร้างชุดข้อมูลจำลองสำหรับมหาวิทยาลัยของท่าน)
แล้วรัน `pnpm workshop:check-mock` จนไม่มีข้อผิดพลาด

ตรวจ PDF หลักสูตรของท่าน:

```bash
pnpm curriculum:check "<file.pdf>"
```

ยังไม่ต้องอัปโหลดข้อมูลของท่านเอง ส่วนนั้นทำในวันที่ 1 ใน Session 3

## ส่งแบบฟอร์มความพร้อม

ในโฟลเดอร์โครงการ:

```bash
pnpm adopter:fresh-check
docker compose images
```

ท่านควรเห็นข้อความ "Fresh-install check passed." และรายการที่มี image ของ
`postgres`, `redis`, `minio` และ `gotenberg` หากข้อใดไม่ผ่าน ให้ค้นหาใน[หน้าการแก้ปัญหา](./troubleshooting.md)
หรือสอบถามผู้จัดก่อนวันอบรม

ผู้สอนจะแจ้งลิงก์แบบฟอร์มความพร้อมในการประชุมเตรียมความพร้อม แบบฟอร์มถามว่า:

- ระบบปฏิบัติการที่ใช้
- `pnpm adopter:fresh-check` ผ่านหรือไม่
- ยืนยันผู้ดูแลระบบแล้วและ `un-wpp` ทำงานเสร็จหรือไม่
- ผู้ให้บริการ AI (Gemini หรือ OpenRouter) และ coding assistant ที่ใช้
- เส้นทางข้อมูล: A, B หรือ C
- แต่ละชุดข้อมูลเป็นข้อมูลจริงหรือจำลอง
- หลักสูตรที่เลือก และ PDF ผ่าน `curriculum:check` หรือไม่
- ปัญหาที่ยังติดอยู่

ส่งภายใน **19 พฤศจิกายน เวลา 18:00 น.** ห้ามใส่ key, ไฟล์ตั้งค่าสภาพแวดล้อม หรือข้อมูลส่วนบุคคลในแบบฟอร์ม
