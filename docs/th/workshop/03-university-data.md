# Session 3: การเชื่อมโยงข้อมูลมหาวิทยาลัย

> **English:** [`03-university-data.md`](../../workshop/03-university-data.md)

**เวลา** หนึ่งช่วงบ่าย ประมาณ 3 ชั่วโมง

**ผลลัพธ์** ท่านนำเข้าข้อมูลมหาวิทยาลัยของท่านเองเข้าสู่ระบบ จากแฟ้มส่งออกจริง แฟ้มจริงผสมแฟ้มที่สร้างขึ้น
หรือชุดข้อมูลจำลองที่สร้างให้มหาวิทยาลัยของท่าน รัน pipeline กับหนึ่งหลักสูตรด้วย AI key ของท่านเอง
และเห็น Deep-Dive ของหลักสูตรนั้นแสดงเนื้อหา

ขั้นตอนเป็นขั้นตอนเดียวกับ [Get Program Deep-Dive working](../tutorials/program-deep-dive.md)
หน้านี้บอกว่าใช้แฟ้มใด และทำตามลำดับใด เพื่อให้ขั้นตอนที่ช้าทำงานไปพร้อมกับงานอื่น

## เริ่มขั้นตอนที่ใช้เวลานานก่อน

pipeline ใช้เวลาประมาณ 20 ถึง 25 นาทีต่อหนึ่งหลักสูตร และใช้เครดิต AI ประมาณ USD 0.40 ถึง 0.80 สำหรับหลักสูตรราว 126 รายวิชา (หลักสูตรที่ยาวกว่าจะมากกว่านี้)
ข้อมูลประชากรของ UN มีขนาดประมาณ 68 MB ให้ทำขั้นตอนสั้น ๆ ก่อน เริ่มขั้นตอนยาวทั้งสอง
แล้วทำงานกับ Setup checklist ระหว่างรอ:

1. Organisation profile (5 นาที)
2. อัปโหลดแฟ้มของท่าน (ประมาณ 20 นาที)
3. แนบ PDF หลักสูตร แล้ว **เริ่ม pipeline**
4. **เริ่ม connector `un-wpp`**
5. ระหว่างที่ทั้งสองทำงาน: อ่าน Setup checklist และส่วน mock API ด้านล่าง

## เตรียมแฟ้มของท่าน

เส้นทางข้อมูลที่ท่านเลือกตาม[แจ้งล่วงหน้า](./early-notice.md#เลือกเส้นทางข้อมูล) เป็นตัวกำหนดว่าจะอัปโหลดแฟ้มใด:

- **A. ข้อมูลจริง** แม่แบบที่ท่านกรอกจากแฟ้มส่งออกของท่านก่อนวันอบรม
  คอลัมน์ของแต่ละชุดอยู่ใน [การนำเข้าข้อมูลจาก spreadsheet](../data-import.md)
- **B. ข้อมูลผสม** สร้างชุดข้อมูลจำลองตามด้านล่าง แล้วใช้แฟ้มของท่านแทนแฟ้มที่สร้างขึ้นในชุดข้อมูลที่ท่านมี
  แฟ้มของท่านต้องใช้รหัสคณะ ภาควิชา หลักสูตร และบุคลากรเดียวกับแฟ้มอื่นที่อัปโหลดร่วมกัน
- **C. ข้อมูลจำลอง** สร้างชุดข้อมูลจำลองตามด้านล่าง แล้วอัปโหลดทั้งหมด

ลบข้อมูลส่วนบุคคลก่อนนำแฟ้มเข้าแล็ปท็อป: ไม่มีเลขประจำตัวประชาชน ไม่มีวันเกิด ไม่มีที่อยู่หรือเบอร์โทรศัพท์

### ไม่มีแฟ้มส่งออก? สร้างชุดข้อมูลจำลองสำหรับมหาวิทยาลัยของท่าน

หากไม่มีแฟ้มส่งออกในมือ มีตัวสร้างที่เขียน spreadsheet ข้อมูลจำลองพร้อมอัปโหลดให้
สำหรับส่วนย่อยที่หลากหลายของมหาวิทยาลัยของท่านเอง ชื่อคณะ ชื่อหลักสูตร และตัวเลขการรับสมัครรอบ 3
มาจากแฟ้ม TCAS สาธารณะ (ดาวน์โหลดจาก mytcas.com เมื่อรันครั้งแรกและเก็บไว้ในแคช)
บุคลากรเป็นโทเค็นที่มีเลขกำกับ เช่น "อาจารย์ 001" ตัวเลขอื่นทั้งหมดเป็นข้อมูลสมมติและระบุว่าเป็น mock
หลักสูตรที่ท่านนำ PDF มาจะรวมอยู่เสมอ และรหัสวิชาอ่านจาก PDF
ต้องระบุหลักสูตรที่มี PDF เล่มหลักสูตรอย่างน้อยหนึ่งหลักสูตร มิฉะนั้น Program Deep-Dive จะทำงานได้ไม่ครบ
ใช้เพื่อฝึกเท่านั้น: ห้ามนำตัวเลขเหล่านี้ไปแสดงเป็นผลจริง ไม่ต้องติดตั้งอะไรเพิ่มนอกจาก Node และ pnpm

**ก่อนวันงาน** เขียนแฟ้มข้อมูลนำเข้า เช่น `my-university.json`:

```json
{
  "university": "มหาวิทยาลัยเทคโนโลยีพระจอมเกล้าธนบุรี",
  "region": "Central",
  "programmes": [
    {
      "name": "วิศวกรรมเครื่องกล",
      "pdf": "pdfs/mechanical-engineering.pdf",
      "level": "BACHELOR",
      "faculty": "คณะวิศวกรรมศาสตร์"
    },
    {
      "name": "วิศวกรรมเครื่องกล",
      "pdf": "pdfs/mechanical-engineering-master.pdf",
      "level": "MASTER",
      "faculty": "คณะวิศวกรรมศาสตร์",
      "name_en": "Master of Engineering Programme in Mechanical Engineering",
      "courses": "courses/mechanical-master.csv"
    }
  ]
}
```

| คีย์ | ความหมาย |
|---|---|
| `university` | ชื่อภาษาไทยของมหาวิทยาลัยท่าน ตรงกับตาราง TCAS ทุกตัวอักษร |
| `region` | หนึ่งใน `Northeast`, `Central`, `North` หรือ `South` ซึ่งเป็นภาคที่ organisation profile มีให้เลือก Central รวมกรุงเทพมหานคร ภาคตะวันออก และภาคตะวันตกด้วย ค่าอื่นจะทำให้สคริปต์หยุด |
| `programmes[].name` | ชื่อหลักสูตรตามที่เขียนใน PDF สะกดต่างเล็กน้อยได้ |
| `programmes[].pdf` | พาธไปยัง PDF หลักสูตร พาธแบบสัมพัทธ์อิงโฟลเดอร์ของแฟ้ม JSON ต้องมีอย่างน้อยหนึ่งหลักสูตรที่ระบุ PDF มิฉะนั้น Program Deep-Dive จะทำงานได้ไม่ครบ หลักสูตรอื่นไม่บังคับ หากระบุ แฟ้มต้องมีอยู่จริง มิฉะนั้นสคริปต์จะหยุด |
| `programmes[].level` | `BACHELOR` (ค่าเริ่มต้น), `MASTER`, `DOCTORAL` หรือ `HIGHER_GRAD_DIPLOMA` |
| `programmes[].faculty` | ชื่อภาษาไทยของคณะ จำเป็นเมื่อระดับไม่ใช่ `BACHELOR` สำหรับหลักสูตรปริญญาตรี ใช้แยกชื่อหลักสูตรที่มีอยู่ในสองคณะ เช่นในตัวอย่าง มจธ. เปิดสอนวิศวกรรมเครื่องกลทั้งในคณะวิศวกรรมศาสตร์และคณะครุศาสตร์อุตสาหกรรมและเทคโนโลยี |
| `programmes[].tcas_code` | ไม่บังคับ ใช้กับหลักสูตรระดับปริญญาตรีเท่านั้น (หลักสูตรบัณฑิตศึกษาไม่มีแถว TCAS) รหัสหลักสูตร TCAS ใช้เมื่อจับคู่ด้วยชื่ออัตโนมัติไม่ได้ และมีลำดับเหนือกว่าเสมอ |
| `programmes[].courses` | ไม่บังคับ แฟ้ม CSV (ไม่ใช่ spreadsheet) ที่ใช้แทนรายวิชาจาก PDF แถวหัวตารางคือ `code,name_th,name_en,credits,category` ค่า `category` เป็นหนึ่งใน General education, Core, Major required, Major elective, Free elective, Thesis / project เว้นว่างหากไม่ทราบ |
| `programmes[].name_en` | ไม่บังคับ ชื่อภาษาอังกฤษที่ใช้ตามนั้นในแฟ้มจำลอง |

รันตัวสร้างหนึ่งครั้งขณะต่ออินเทอร์เน็ต เพื่อให้แฟ้ม TCAS ถูกเก็บในแคช

**สร้าง**

```bash
pnpm workshop:mock my-university.json
```

ตัวเลือก: `--size small|medium` (ค่าเริ่มต้น `small`), `--seed N` (ข้อมูลนำเข้าและ seed เดียวกันให้แฟ้มเหมือนกัน),
`--out DIR` (ค่าเริ่มต้น `./workshop-mock-out`) และ `--offline` (ใช้เฉพาะแฟ้ม TCAS ในแคช), `--cache DIR` (ที่เก็บแคช TCAS) และ `--tcas-file PATH:YEAR:ROUND` (ใช้แฟ้ม TCAS ที่ท่านมีอยู่แล้ว แฟ้มจะถูกคัดลอกเข้าแคช และการรันด้วย `--offline` ครั้งต่อไปจะอ่านเฉพาะแฟ้มที่การรันนั้นใช้)
แฟ้ม TCAS ถูกเก็บแคชใน `<out>/.cache` หากวันงานไม่มีอินเทอร์เน็ต ให้รันหนึ่งครั้งล่วงหน้า แล้วใช้ `--offline`

ท่านควรเห็น `TCAS matches:` ตามด้วยหนึ่งบรรทัดต่อหนึ่งหลักสูตรที่ท่านระบุ เช่น
`วิศวกรรมคอมพิวเตอร์ -> programme MOCK-P004: TCAS course code 10140107300507A, faculty '...', programme '...'`
แล้วจึงเป็นบรรทัด `note:` ตรวจว่าแต่ละบรรทัดตรงกับหลักสูตรที่ตั้งใจ
หากจับคู่ผิด หรือสคริปต์หยุดพร้อมรายการตัวเลือก ให้ตั้งค่า `tcas_code` ของหลักสูตรนั้น (หรือ `faculty` เมื่อตัวเลือกอยู่ต่างคณะกัน) แล้วรันใหม่

รหัสออก 0 หมายถึงเขียนแฟ้มแล้ว รหัสออก 2 หมายถึงไม่ได้เขียนอะไรเลย ให้อ่านข้อความด้านบน
ชื่อรายวิชาภาษาไทยที่อ่านจาก PDF อาจสูญเสียช่องว่างระหว่างคำไทย หรือถูกเว้นว่างเมื่อข้อความใน PDF เสียหาย บรรทัด `note:` จะนับจำนวนที่เว้นว่าง

**ตรวจสอบ**

```bash
pnpm workshop:check-mock workshop-mock-out my-university.json
```

ท่านควรเห็นหลักสูตรระดับปริญญาตรีทุกหลักสูตรถูกจับคู่ และไม่มีข้อผิดพลาด การตรวจนี้พิสูจน์ว่าแฟ้มผ่านตัวนำเข้าของระบบ
และ connector `tcas` จะจับคู่หลักสูตรได้ รหัสออก 0 หมายถึงผ่านทุกการตรวจ 1 หมายถึงมีการตรวจที่ไม่ผ่าน (บรรทัดด้านบนระบุไว้) 2 หมายถึงอาร์กิวเมนต์ผิดหรืออ่านแฟ้มไม่ได้

## นำเข้าข้อมูลมหาวิทยาลัยของท่าน

### Organisation profile

เปิด `/admin/organization` แล้วกรอกแท็บ "Identity" ตามที่
[ขั้นตอนที่ 1](../tutorials/program-deep-dive.md#ขั้นตอนที่-1-ตั้งค่า-organisation-profile)
อธิบาย ด้วยชื่อมหาวิทยาลัยของท่าน ชื่อภาษาไทยต้องตรงกับตาราง TCAS ทุกตัวอักษร
มิฉะนั้น connector `tcas` จะจับคู่ไม่ได้เลย หากใช้ชุดข้อมูลจำลอง ให้พิมพ์ชื่อภาษาไทยและเลือก Region
ให้ตรงกับที่ `README.txt` ในโฟลเดอร์ผลลัพธ์ระบุไว้ เว้น OpenAlex institution ID ว่างไว้ เว้นแต่ท่านทราบ ID ของมหาวิทยาลัย

คลิก "Create organisation" ท่านควรเห็นชื่อปรากฏที่ส่วนหัว

### อัปโหลดแฟ้ม

อัปโหลดหนึ่งแฟ้มต่อหนึ่งชุดข้อมูล ตามลำดับของชุดข้อมูลในหน้า `/admin/data-setup` จากบนลงล่าง
แฟ้มของชุดข้อมูลจำลองมีหมายเลขตามลำดับนี้อยู่แล้ว อัปโหลดแต่ละแฟ้มที่หน้าชุดข้อมูลของตน
ด้วยปุ่ม "Upload filled template" ตามที่อธิบายใน
[ขั้นตอนที่ 2](../tutorials/program-deep-dive.md#ขั้นตอนที่-2-อัปโหลดโครงสร้างองค์กรและหลักสูตร)

จากนั้นอัปโหลด **University Rankings** ตามที่มีมา: เปิดหน้าของชุดข้อมูลนี้ ดาวน์โหลดแม่แบบที่กรอกไว้ล่วงหน้า
แล้วอัปโหลดกลับโดยไม่แก้ไข

ท่านควรเห็นแต่ละการอัปโหลดในประวัติ "Uploads" พร้อมจำนวนแถว เมื่อแฟ้มถูกปฏิเสธ ข้อความจะระบุแถวและคอลัมน์
กฎอยู่ใน [การนำเข้าข้อมูลจาก spreadsheet](../data-import.md)

การอัปโหลดนับเป็นข้อมูลจริง เช่นเดียวกับการรัน connector กฎของ Setup checklist ที่ว่า
"แถวตัวอย่างไม่ทำให้รายการเป็นสีเขียว" หมายถึง connector จำลองที่มากับระบบ ไม่ใช่แฟ้มที่อัปโหลด
ไม่ว่าแฟ้มนั้นจะสร้างขึ้นหรือไม่

### Connector สาธารณะ

เมื่ออัปโหลดครบ เปิด `/admin/data-sources` แล้วรัน:

- `un-wpp` ไม่ต้องใช้ key โหลดประมาณการประชากรของ UN ที่ใช้ในส่วน Demographic outlook
- `tcas` จับคู่หลักสูตรของท่านด้วยชื่อภาษาไทยของมหาวิทยาลัย
- `openalex-works` ด้วย key แบบฟรี สำหรับเส้นทาง A หรือ B connector นี้จับคู่บุคลากรจำลองไม่ได้
  เพราะเป็นโทเค็น ไม่ใช่บุคคลจริง
- `kmitl-skill-mapping` เฉพาะเมื่อผู้จัดให้ข้อมูลรับรองของ KMITL ใช้เวลาประมาณหนึ่งชั่วโมง
  จึงควรเริ่มก่อน pipeline แล้วรันคำสั่งใน
  [ทักษะตลาดแรงงาน](../tutorials/program-deep-dive.md#labour-market-skills)

หากท่านอัปโหลดแฟ้ม Career Skill Demand (ชุดข้อมูลจำลองมีแฟ้มนี้) ให้เชื่อมชื่อทักษะเข้ากับอนุกรมวิธานทักษะ
จากรากของ repository ใช้เวลาประมาณ 13 วินาทีสำหรับชื่อในชุดจำลอง:

```bash
pnpm skills:normalise --source=linkedin --auto-promote
```

หากไม่รัน รายการ Setup checklist "Labour market alignment" และ "Demand match filled"
จะยังขาด และ pipeline phase 3 จะข้าม demand match

### PDF หลักสูตรและ pipeline

1. ตรวจสอบ PDF ก่อน:

```bash
pnpm curriculum:check "<file.pdf>"
```

2. เปิด `/admin/programs` แล้วคลิกหลักสูตรของท่าน
3. ในแท็บ "Files" (แสดงเป็น "Files (0)" จนกว่าจะแนบแฟ้ม) เลือกบทบาท `CURRENT_CURRICULUM` แล้วอัปโหลด PDF
4. ในแท็บ "Pipeline history" คลิก "Run full pipeline" หรือรันจาก terminal ด้วยรหัสหลักสูตร:

```bash
pnpm programs:pipeline <programme-code>
```

ท่านควรเห็นแต่ละ phase เสร็จทีละขั้น หากท่านอัปโหลดรายการรายวิชาของหลักสูตร (ชุดข้อมูลจำลองมีแฟ้มนี้)
phase รายวิชาจะรายงานว่ารายการมาจากการอัปโหลด ซึ่งเป็นเรื่องปกติ เพราะรายการที่อัปโหลดมีลำดับเหนือกว่า PDF เสมอ
ส่วนอื่นของ pipeline อ่าน PDF เพื่อดึงคำอธิบายหลักสูตร ผลลัพธ์การเรียนรู้ และคำอธิบายรายวิชา

ค่าใช้จ่ายของ pipeline เพิ่มตามจำนวนรายวิชาในหลักสูตร: วัดได้ USD 1.30 กับหลักสูตร 166 รายวิชา เทียบกับ USD 0.40 ถึง 0.80 กับหลักสูตร 126 รายวิชา

### Setup checklist

เปิดแท็บ "Setup checklist" ของหลักสูตร ตาม
[ขั้นตอนที่ 6](../tutorials/program-deep-dive.md#ขั้นตอนที่-6-ทำให้-setup-checklist-เป็นสีเขียว)
รายการสีแดงแต่ละรายการระบุสิ่งที่ขาด

บางรายการยังคงเป็นสีแดงหรือ "not applicable" ซึ่งถูกต้องแล้ว:

- **JobThai** แสดง "not applicable" เพราะเป็นข้อมูลเชิงพาณิชย์
- รายการด้าน **ตลาดแรงงาน** (demand match, labour-market alignment) เว้นแต่ท่านอัปโหลดแฟ้ม
  Career Skill Demand และรันคำสั่งด้านทักษะ หรือรัน `kmitl-skill-mapping` และคำสั่งของ connector นั้นแล้ว
- **งานวิจัยจาก OpenAlex** ในชุดข้อมูลจำลอง เพราะข้อมูลผลงานตีพิมพ์มาจากการอัปโหลดแทน

รายการอื่นทั้งหมดควรเป็นสีเขียวเมื่อ pipeline ทำงานเสร็จ รายการสีแดงอื่นจะระบุแฟ้มหรือการรัน connector ที่ยังขาด

### เริ่มใหม่

หากต้องการลบข้อมูลที่นำเข้า ให้ใช้ "Start over" ที่หน้าชุดข้อมูลแต่ละชุด โดยไล่จากชุดที่อัปโหลดหลังสุดกลับไป
และลบโฟลเดอร์ผลลัพธ์ของชุดข้อมูลจำลองด้วย
