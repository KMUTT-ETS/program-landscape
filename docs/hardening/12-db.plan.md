# Plan — Prompt 12: Database safety

**Mode:** code change. Targeted to gaps in the existing DB stack.

## Reads

- `packages/db/prisma/schema.prisma` (sizeable; sample only).
- `packages/db/prisma/migrations/*` (every migration SQL file).
- `docs/migration-policy.md`.
- `scripts/pre-deploy-snapshot.mjs`.
- `.github/workflows/pr.yml` + `release.yml`.
- High-write service methods — focused grep: `prisma.\w+\.(create|update|delete|upsert)` clustered in one method.

## Order of work

1. **Migration linter** — `scripts/migration-linter.ts`. Reads every `.sql` file under `packages/db/prisma/migrations/`, fails with non-zero exit + a clear pointer if it sees:
   - `DROP TABLE`
   - `DROP COLUMN` / `ALTER TABLE … DROP`
   - `RENAME COLUMN` / `RENAME TO` (rename = drop + add for callers)
   - `ALTER COLUMN … TYPE` (data-bearing change)
   - `ALTER COLUMN … SET NOT NULL` without an explicit `DEFAULT`
   - `TRUNCATE`
   ...UNLESS the file (or the line) carries `-- migration-linter: allow-destructive (reason: …)`.

   Wire into `.github/workflows/pr.yml` as a separate job that runs on every PR.

2. **Transaction audit + fixes** — grep for service methods doing >1 prisma write. Flag the worst offenders. Wrap the obvious ones in `$transaction`. Document the rest with a "no shared invariant; not transactional" note where it's safe.

3. **Connection pool** — Prisma reads `connection_limit` from the DATABASE_URL query string. Document the math:
   - postgres `max_connections=100` (default for the postgis image)
   - api: 10
   - ingestion: 8 (workers in flight)
   - web: 5 (Next/server-action queries)
   - admin tools (one-shots, seed scripts): 3
   - reserved for migrations + ad-hoc psql: 5
   - **total: 31** — well within the 100 ceiling.

4. **Slow query log** — extend `infra/postgres/init/01-extensions.sql` (or add a sibling `02-tuning.sql`) to set `log_min_duration_statement = 250` + `log_connections = on` + `log_disconnections = on`. Postgres logs land in the container's stdout, captured by the `json-file` driver per compose.

5. **Snapshot drill** — confirm `pre-deploy-snapshot.mjs` exits non-zero on failure AND `deploy.sh` aborts on that exit. The script should produce a restorable `pg_dump` (custom-format) under `/opt/program-landscape/backups/pre-deploy/<sha>-<ts>.dump`.

## Deliverables

- `scripts/migration-linter.ts` (new)
- `apps/api/test/migration-linter.test.ts` (or `packages/db/test/`) — unit tests on hand-crafted SQL strings
- Updated `.github/workflows/pr.yml`
- Updated `infra/postgres/init/02-tuning.sql` (new)
- Updated `.env.prod.example` (DATABASE_URL pool annotation)
- Possibly a small `prisma.$transaction` wrap in 1-2 services (the worst offenders)
- `docs/hardening/12-db.report.md`

## Out of scope

- PgBouncer (single-instance prod doesn't need it yet; documented).
- Adding optimistic-version columns to every model (would touch every table; contained scope per the prompt — only the read-modify-write paths that *demonstrate* a lost-update risk).
- Row-level security / fine-grained Postgres roles (Block D / post-launch).
- Migrating to logical replication or zero-downtime swaps.
